## Требования

| Что | Зачем | Обязательно |
|---|---|---|
| Linux, x86-64 | на нём Datum разрабатывается и проверяется | да |
| Python **3.11** | бэкенд; замок зависимостей собран именно под 3.11 | да |
| Node.js 22.12+ и npm | окно (Electron 44, Vite) | да |
| компилятор C++, `make`, Python 3 | сборка нативного модуля терминала `node-pty` | да |
| [Claude Code](https://claude.com/claude-code) — или другой агент с MCP | работу ведёт агент; окно, навык и критик — под Claude Code | да |
| ElegooSlicer | нарезка из Datum (`datum slice`) | нет |

Места на диске нужно около 2–3 ГБ: Electron, мешер fTetWild, MuJoCo и (на
x86-64) Intel MKL для быстрого решателя МКЭ — одна она около 700 МБ.

Если в системе Python не 3.11, поставьте его рядом, не трогая системный,
например через [uv](https://docs.astral.sh/uv/) (`uv python install 3.11`, а
дальше вместо `python3.11` — `$(uv python find 3.11)`) или pyenv.

## Установка

```sh
git clone https://github.com/HelpFreedom/Datum.git
cd Datum
```

**1. Окружение Python.**

```sh
python3.11 -m venv .venv
.venv/bin/pip install --require-hashes -r py/requirements.lock
.venv/bin/pip install --no-deps -e py
```

Первая команда ставит зависимости ровно тех версий и с теми хешами, что
записаны в `py/requirements.lock`: подменённый пакет не установится. Вторая
ставит сам Datum в режиме разработки (`-e`) — правки в `py/` видны сразу.

**2. Окно.**

```sh
scripts/bootstrap.sh
npm run build
```

`scripts/bootstrap.sh` ставит пакеты npm с **запрещёнными** скриптами установки
(`.npmrc`) и явно собирает два пакета, которым они нужны: `esbuild` и
`node-pty`, а затем скачивает бинарник Electron (около 100 МБ, сверяется по
контрольным суммам). В конце он проверяет, что всё загружается. `npm run build` собирает
окно (`apps/ui`) и оболочку (`apps/shell`).

**3. Проверка.**

```sh
.venv/bin/python -m datum.cli status
npm start -- examples/latch
```

Должно открыться окно с коробкой и крышкой примера `latch`.

**4. Необязательно.**

```sh
make install   # ссылка ~/.local/bin/datum → scripts/datum
make mcp       # .mcp.json в корне репозитория
```

После `make install` команда `datum` доступна в терминале, dmenu и меню
приложений (если `~/.local/bin` есть в `PATH`). Это ссылка, а не копия:
обновление репозитория сразу видно.

**Обновление.** `git pull`, затем повторить шаги 1 и 2 (если изменились
`py/requirements.lock` или `package-lock.json`) и `npm run build`.

## Запуск

| Команда | Что делает |
|---|---|
| `datum` | окно с пустым проектом «Без названия» (`~/.local/share/datum/untitled/`) |
| `datum <каталог>` | окно с этим проектом |
| `datum <файл.datum>` | распаковать архив рядом с ним и открыть |
| `datum <команда> …` | обычный CLI: `datum check …`, `datum export …`, `datum --help` |

Без `make install`: `.venv/bin/python -m datum.cli <команда> …` и
`npm start -- <проект или архив>`.

Окно отрывается от терминала; его журнал — `~/.local/state/datum/window.log`.
Ошибку запуска из dmenu показывает уведомление (`notify-send`).

**Ярлык Windows (WSL 2 с WSLg).** После установки Datum в Linux запустите
этот скрипт в Windows PowerShell из каталога, где доступен репозиторий:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\install-wsl-shortcut.ps1 -Distribution Debian -Checkout /home/alex/Datum
```

Подставьте имя дистрибутива из `wsl --list --verbose` и абсолютный путь
к репозиторию внутри него. Ярлык «Datum» на рабочем столе Windows открывает
приложение без указанного проекта, через WSLg. Повторный запуск возвращает
окно с текущим проектом. Консоль запускается скрыто.
При отказе Windows показывает код завершения и путь к журналу окна.
Повторный запуск скрипта обновляет ярлык. Параметр `RemoteSigned` применяется
к запущенному процессу PowerShell.

Коды возврата CLI: `0` — прошло, `1` — проверки не прошли, `2` — неверные
аргументы, `3` — операция отказала (нет проекта, ошибка в скрипте), `130` —
прервано.

## Работа с агентом

Datum — редактор для ИИ-агента: конструирует и считает агент, человек ставит
задачу, отвечает на вопросы и решает, когда готово. Рассчитан он на
[Claude Code](https://claude.com/claude-code).

**Подготовка.** Поставьте Claude Code так, чтобы `claude` был в `PATH` (или в
`~/.local/bin/claude`; другой путь — переменной `DATUM_CLAUDE`), и войдите в
него один раз в терминале. В окне Datum агент запускается кнопкой «Запустить
Claude Code» в нижней панели — сам он не стартует: открыть окно — ещё не
значит позвать агента.

**Как ставить задачу.** Говорите о замысле, а не о командах:

- что это и для чего: «держатель для двух отвёрток на стену», «рука,
  поднимает 100 г на 15 см»;
- чем делать: материал, принтер или способ изготовления, покупные детали
  (серва, подшипник, винты) — с моделью или паспортом, если есть;
- что известно точно, а что нет: «диаметр мерил штангенциркулем — 8.1 мм»
  станет параметром `measured` с источником, неизвестное агент объявит
  угаданным с диапазоном и скажет, стоит ли его мерить;
- просите показать: агент кладёт деталь, срез или подпись прямо в окно, а
  вы возвращаете свой вид одной кнопкой;
- указывайте на месте: выделите деталь, наведите штангенциркуль и скажите
  «вот здесь» — агент видит, что выбрано и откуда вы смотрите.

**Что получает встроенный агент:**

- все операции Datum как инструменты MCP (`mcp__datum__*`) — те же, что CLI и
  кнопки окна;
- навык с правилами конструирования (`plugin/skills/datum`), подключаемый
  плагином (`--plugin-dir plugin`) в любом проекте;
- вид окна: что выделено и скрыто, откуда смотрит камера, что выбрано
  штангенциркулем (`window_state`), весь стол картинкой (`scene_view`); и
  может показать вам деталь, срез или подпись (`window_show`);
- ИИ-критика (`plugin/agents/critic.md`): когда проект готов, свежий агент
  с инструментами только для чтения ищет, что упущено (не больше двух кругов
  доработки), и команду `/datum:audit` — независимый аудит по темам;
- журнал решений проекта (`JOURNAL.md`): новая сессия получает сводку
  проекта сама и продолжает с того места, где остановились.

**Без окна.** `claude` в обычном терминале тоже видит инструменты: в каталоге
проекта — через `.mcp.json`, который пишет `datum init`; в репозитории —
после `make mcp`. Если окно открыто, правки агента видны в нём сразу.

**Другой агент.** Какого агента использовать — выбор ваш: любой агент с
поддержкой MCP подключается к тем же операциям командой
`datum mcp --stdio` (или `.venv/bin/python -m datum.cli mcp --stdio`).
Окно, навык, критик и хуки сделаны под Claude Code; другому агенту правила
навыка стоит дать самому — они в `plugin/skills/datum/SKILL.md` и
`references/`.

## Первый проект

Обычно всё это делает агент по вашей просьбе. Здесь то же самое — руками,
чтобы было видно, что лежит под капотом: открытые файлы и команды.

```sh
datum init ~/parts/plate
```

Создаётся пустой проект: `datum.toml` (принтер, стол, материал),
`params/base.yaml`, `checks/checks.yaml`, `NOTES.md`, пустой `parts/`.

**Параметры.** Допишите в `params/base.yaml`:

```yaml
PLATE_W: {value: 40.0, unit: mm, provenance: chosen, reason: "ширина пластины"}
PLATE_T: {value: 3.0, unit: mm, provenance: chosen, reason: "толщина"}
HOLE_D:
  value: 3.4
  unit: mm
  provenance: assumed
  range: [3.2, 3.6]
  reason: "под винт M3, посадка не проверена на этом принтере"
```

У каждого числа есть происхождение:

| `provenance` | значит | обязательно рядом |
|---|---|---|
| `measured` | намерено | `source` — чем и как |
| `assumed` | угадано | `range` — в каких пределах может быть |
| `derived` | выведено формулой | `expr` |
| `standard` | из стандарта или паспорта | `ref` |
| `chosen` | решение конструктора | `reason` |

**Деталь.** Создайте `parts/plate.py`:

```python
"""Пластина с отверстием под винт M3."""

from datum.build import P, centre_on_bed, part
from datum.geom import box, cyl_z, diff


@part("пластина", print_up="+Z")
def build():
    w = P.PLATE_W
    plate = box(-w / 2, w / 2, -w / 2, w / 2, 0, P.PLATE_T)
    hole = cyl_z(P.HOLE_D, -1, P.PLATE_T + 1)
    return centre_on_bed(diff(plate, [hole]))
```

- `P.ИМЯ` — значение параметра; Datum запоминает, какие параметры читает деталь;
- `print_up="+Z"` — какой стороной вверх деталь печатается; проверки печатности
  берут позу отсюда и сами её не выбирают;
- `centre_on_bed` ставит деталь в центр стола.

Весь API — `plugin/skills/datum/references/api.md` (генерируется из кода).

**Сборка, проверки, выгрузка.**

```sh
datum build  ~/parts/plate
datum check  ~/parts/plate
datum sweep  ~/parts/plate
datum export ~/parts/plate
```

`check` гоняет базовые проверки печатности (стенка, полости, стол,
нависания) и всё, что объявлено в `checks/checks.yaml` (каталог —
`datum checks`). `sweep` прогоняет каждое `assumed`-число по его диапазону и
говорит, от какого зависит вердикт, — это то, что стоит померить первым.
`export` пишет 3MF и STL в `output/` в позе печати; «не готов к печати» —
первая строка отчёта, если какая-то проверка не прошла.

Откройте проект в окне — `datum ~/parts/plate`. Скрипт можно править в любом
редакторе: окно увидит изменение файла само.

## Окно

- **Сверху** — меню, состояние проекта («собирается…», «не прошло проверок:
  2»), кнопка «Проверить», точка архива (зелёная — сохранено).
- **Слева** — сцена (детали, видимость, порядок сборки, корзина), чужие
  модели, версии.
- **Справа** — свойства выделенной детали, проверки худшими вперёд, параметры
  с происхождением (правятся прямо здесь).
- **Снизу** — Claude Code и лента вызовов.

Во вьюпорте: куб видов, срез по X/Y/Z, разнесение, инструменты слева.
Штангенциркуль (`D`) подсвечивает вершину, ребро, окружность или дугу, центр
отверстия или грань; щелчок по окружности даёт Ø, второй элемент —
расстояние (с ΔX ΔY ΔZ) или угол; `Shift` — точка на поверхности.
Перенос (`M`, шаг 1 мм, с `Shift` — 0.1) и поворот (`R`, шаг 15°, с `Shift` —
1°) — правка проекта: положение пишется в `placement.yaml`, и проверки видят
деталь там же. `Delete` удаляет деталь целиком (с её моделью и проверками) в
корзину проекта, `Ctrl+Z` возвращает. Все клавиши — `?`.

Камера — как в слайсере: левая кнопка вращает вокруг вертикали стола, правая
или средняя двигает, колесо приближает к курсору постоянным шагом (с `Shift` —
мельче), `H` возвращает исходный вид.

## Сохранение и архив `.datum`

Рабочее место проекта — папка, и каждая правка пишется в неё сразу. Архив
`.datum` — проект одним файлом, чтобы хранить, пересылать и открывать снова:

- «Файл → Сохранить как…» (`Ctrl+Shift+S`) — упаковать в новый файл;
- «Сохранить» (`Ctrl+S`) — туда, откуда проект открыт или куда сохранялся;
- «Файл → Проекты…» (`Ctrl+O`) — недавние проекты, переименование, «новый из
  этого»;
- `datum файл.datum` или «Открыть архив .datum…» — распаковать рядом и открыть.

В архив не идут кеш `.datum/`, выгрузка `output/` и символьные ссылки. Из
командной строки: `datum save <проект> --dest файл.datum`,
`datum unpack файл.datum`. Распаковка чужого архива проверяет пути, ссылки и
размер до записи.

Версии: `datum snapshot <проект> <имя>` снимает версию, `datum diff` и вкладка
«Версии» показывают, что изменилось, — числами и картинкой формы.

## Чужие модели

«Открыть файл…» или «Файл → Импортировать модель…» ставит 3MF/STL на стол:
каждый объект файла становится своей деталью (`parts/<имя>.py`, модель в
`imported/`). 3MF читается так, как его печатает слайсер (Bambu, Orca,
Elegoo): вычитаемые части вычитаются, модификаторы пропускаются.

Модель-образец (например, скан предмета под ложемент) — `datum import`: она
видна полупрозрачной и в проверки не идёт. `datum footprint` строит контур
предмета в плане, `datum diagnose` / `datum repair` — диагностика и ремонт
чужого меша.

## Выгрузка и нарезка

`datum export <проект>` пишет 3MF и STL в позе печати. Записанный файл
перечитывается и сверяется с деталью; в 3MF записан рецепт печати.

`datum slice <проект>` режет консольным ElegooSlicer и пишет проект,
который его окно открывает как свой. Слайсер ищется как `elegooslicer` в
`PATH` или по переменной `DATUM_ELEGOO_SLICER`; профили — в системном каталоге
слайсера или по `DATUM_ELEGOO_PROFILES`. Нарезанное сверяется с подвалом
G-code (профили, тип стола, правки), `datum slice-report` разбирает G-code по
слоям и находит острова без опоры.

Ещё: `datum mass` (масса по настройкам печати, сверена с G-code),
`datum bom` (ведомость), `datum guide` (сборочная инструкция в картинках),
`datum coupon` (пробный образец посадки).

## Механизмы и симуляция

Механизм объявляется в скрипте детали (`@mechanism`, звенья, суставы,
приводы, сценарии) — см. `examples/arm` и
`plugin/skills/datum/references/simulation.md`.

```sh
datum sim-list   examples/arm               # механизмы и сценарии
datum sim        examples/arm рука перенос  # момент, отставание, устойчивость, задевания
datum sim-stress examples/arm рука перенос  # напряжения звеньев в худший момент (МКЭ)
datum sim-export examples/arm рука          # GLB с движением, MJCF, URDF
```

В окне кнопка «Симуляция» открывает проигрыватель с графиками моментов и
картой нагрузки (на анимации в README — именно он).

Трение, КПД, люфт и инерция ротора учитываются только объявленные, с
источником; не объявлены — отчёт так и пишет: «запас оптимистичен».

## Разработка

```sh
make check   # всё перед коммитом: тесты бэкенда и окна, бюджеты, самопроверка МКЭ
make ui      # сценарии живого окна (нужен дисплей)
make audit   # опись зависимостей: 0 — чисто, 1 — находки, 2 — отчёт неполон (нет сети)
```

По отдельности: `cd py && ../.venv/bin/python -m pytest tests -q` — бэкенд,
`npm test` — типы и vitest окна и оболочки,
`.venv/bin/python scripts/budget.py` — бюджеты времени.

Тесты `py/tests/corpus` работают на внешнем корпусе прежних проектов
(`DATUM_CORPUS`); без него они пропускаются. Тест нарезки с настоящим
слайсером пропускается, если ElegooSlicer не найден.

Замок зависимостей обновляется так (долго: считаются хеши колёс под все
платформы):

```sh
cd py && pip-compile --generate-hashes --strip-extras --extra server --extra mcp \
  --extra mesh --extra sim --extra dev -o requirements.lock pyproject.toml
```

Устройство целиком — [architecture.md](architecture.md), охрана —
[security.md](security.md), правила для правок — [CONTRIBUTING.md](../CONTRIBUTING.md).

## Частые проблемы

**`pip` ругается на хеши или не находит версию.** Окружение создано не
Python 3.11. Удалите `.venv` и создайте заново `python3.11 -m venv .venv`.

**`scripts/bootstrap.sh` падает на `node-pty`.** Нет компилятора: поставьте
`base-devel` (Arch), `build-essential` (Debian/Ubuntu) или
`gcc-c++ make` (Fedora).

**`datum: нет Electron`** — не выполнен `scripts/bootstrap.sh`.
**`datum: окно не собрано`** — не выполнен `npm run build`.

**Окно не открывается, в журнале ошибка про песочницу Chromium**
(`SUID sandbox helper`). Некоторые дистрибутивы (например, Ubuntu 24.04)
запрещают Electron непривилегированные пространства имён. Datum песочницу не
отключает и отключать не предлагает; сделайте помощника песочницы таким, как
требует Electron:

```sh
sudo chown root node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
```

**Агент не запускается.** `claude` не найден в `PATH` и в `~/.local/bin`, или
вы ещё ни разу не входили в Claude Code в терминале.

**Что-то ещё.** Журнал окна — `~/.local/state/datum/window.log`, состояние
бэкенда — `datum status`. Issue с шагами повторения очень поможет.
