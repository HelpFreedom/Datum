## 1. Назначение и принципы

Datum — среда проектирования деталей для 3D-печати (FDM), в которой
конструкцию ведут вместе человек и ИИ-агент (Claude Code). Деталь — это
Python-скрипт, а не дерево фич; числа — параметры с происхождением; готовность
к печати решают проверки, а не впечатление от картинки.

Главная цель — ловить ошибки конструкции **до печати**. Она выросла из
корпуса прежних проектов (внешний каталог, только чтение), где версии
печатались по три раза из-за ошибок, видимых только в расчёте: деталь
«держала» касанием, а не объёмом; запаянная полость; упругий язычок
тоньше стенки и т. п.

Принципы, на которых держится всё остальное:

| принцип | как воплощён |
|---|---|
| У каждого числа есть происхождение | `params/base.yaml`: `measured` / `assumed` (с диапазоном) / `derived` / `standard` / `chosen`; правка только операцией `param_set` |
| Угаданное проверяют развёрткой | `sweep_assumed` гоняет проверки по диапазону каждого `assumed` и говорит, что мерить в первую очередь |
| Что показано, то и измерено | окно, проверки и экспорт берут одну и ту же сетку из кеша; окно ничего не пересчитывает само |
| Замысел объявляют, а не угадывают | `assembly.yaml` (как ставится), `@part(print_up=…)` (как печатается), `@part(zones=…)` (что упруго нарочно) |
| Провал приносит доказательство | у проверки — сечение или график, у стража — место полости и подсказка `section(...)` |
| Человек и агент равны в возможностях | одна операция реестра даёт команду CLI, инструмент MCP и маршрут HTTP |
| Ответ МКЭ — вилка, а не число | лестница сеток, односторонняя вилка, тест заплаты на той же сетке |
| Охрана не ослабляется настройками | нет `--host`, нет списков разрешённых `Origin`, нет `Access-Control-*` |

## 2. Общая архитектура

### 2.1 Процессы

```
┌──────────────────────── Electron (apps/shell, main) ────────────────────────┐
│  main.ts: окно, меню снято, CSP, охрана навигации, перезапуск рендерера     │
│  backend.ts ── spawn ──►  python -m datum.cli serve <проект> --handshake …  │
│  agent.ts   ── node-pty ─► claude --mcp-config … --plugin-dir plugin/       │
│        ▲ IPC (preload: window.datum)                                         │
│  ┌─────┴──────── renderer (apps/ui, React + three.js) ───────────────┐       │
│  │ http://127.0.0.1:<порт>/  — то же происхождение, что сервер        │       │
│  │ HTTP /api/ops/*  + WS /ws (токен первым кадром)                    │       │
│  └────────────────────────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────────────────────┘
            │ HTTP/WS (петля)                         │ stdio
            ▼                                         ▼
┌──── Python-сервер (FastAPI + uvicorn) ────┐   ┌── MCP-процесс ─────────────┐
│ один сервер = один проект                  │◄──│ python -m datum.cli mcp    │
│ JobManager: семафор, очередь заданий      │HTTP│ тонкий клиент: каждую      │
│ EventHub: кольцо 1000 событий             │   │ операцию шлёт серверу,     │
│ watch.py: правки файлов → doc.changed     │   │ если он жив                │
│        │ fork на каждую изолир. операцию  │   └────────────────────────────┘
│        ▼                                  │
│  BuildWorker: setsid, rlimits, без сети,  │
│  перила импорта/записи; пишет кеш сам     │
└───────────────────────────────────────────┘
            │
            ▼
     <проект>/.datum/cache  (sqlite + объекты по sha256)
```

- **Оболочка** (Electron) поднимает Python-сервер, открывает окно на его
  происхождении и отдаёт окну токен через IPC. Больше она ничего не считает.
- **Сервер** — один на проект, только на петле. Исполняет операции реестра,
  рассылает события, раздаёт бандл окна и артефакты кеша.
- **Воркер** — `fork` сервера на каждую операцию, исполняющую код проекта
  (29 из 39). Пределы памяти и процессорного времени, запрет сети, своя группа
  процессов, гибель вместе с родителем.
- **Окно** — React-приложение; состояние «от сервера» (`store/doc`) отделено
  от раскладки и инструментов (`store/ui`); вьюпорт — императивный three.js.
- **Агент** — системный `claude` в pty внутри дока окна. Видит Datum через
  MCP-сервер, который в режиме тонкого клиента шлёт вызовы тому же серверу —
  поэтому правка агента сразу видна в окне.
- **CLI** (`datum …`) — та же операция реестра, исполненная в своём процессе
  (изолируемые — в воркере).

### 2.2 Слои бэкенда

```
             tools/ (реестр операций) ── cli_adapter / mcp_adapter / server/app
                       │
        ┌──────────────┼───────────────┬──────────────┐
        ▼              ▼               ▼              ▼
      doc/          checks/          io/            viz/
   (проект,        (каталог 34      (STL/3MF/GLB,  (растеризатор,
   параметры,       проверок,        слайсер)       сечения,
   снимки,          исполнитель,                    графики)
   архив)           развёртка)
        │              │    └──► fem/ (P2-МКЭ, fTetWild)
        ▼              ▼
     build/  (декоратор @part, контекст сборки, кеш, воркер, перила)
```

Правило слоёв: `manifold3d` импортирует только `geom/` (и `std/` через него).
Одно исключение направления — `geom/sweep.py` берёт разбор направления из
`checks/motion.py`.

## 4. Проект на диске

### 4.1 Каркас

```
<проект>/
  datum.toml            манифест: принтер, стол, сопло, слой, материал, страж, кеш
  params/base.yaml      реестр параметров с происхождением
  parts/*.py            скрипты деталей (@part); файлы на «_» пропускаются
  lib/**/*.py           помощники проекта, импорт как `lib.*`
  checks/checks.yaml    проверки из каталога
  checks/custom.py      проектные проверки (@check)
  assembly.yaml         порядок сборки, способ постановки, направление вставки
  placement.yaml        положение деталей на столе (пишут окно и part_place)
  imported/<имя>/       чужие модели: source.*, result.stl|3mf|obj|ply, meta.json
  snapshots/*.json      снимки версий
  output/               выгрузка (3MF, STL, G-code)
  NOTES.md, .gitignore, .mcp.json
  .datum/               служебное (в архив .datum не входит как кеш)
    cache/index.sqlite, cache/objects/<2 hex>/<sha256>.<ext>
    window.json         что показывает окно (для агента)
    archive.json        куда сохранён архив и отпечаток файлов
    trash/<штамп>-<стем>/   корзина удалённых деталей
    imported-views.json памятка о GLB образцов импорта
    slice/              временные 3MF для нарезки
```

Новый проект — `datum init <каталог>` (`doc/scaffold.py`): манифест,
параметры и проверки без единой записи (только образцы в комментариях),
пустой `parts/`. С 2026-10-23 проект всегда пустой (решение владельца):
прежний кубик-образец и флаг `--empty` убраны.

### 4.2 `datum.toml`

```toml
schema = 1
name = "hello"
units = "mm"
[printer]
profile = "elegoo-cc2-0.4"
bed = [256, 256, 256]
nozzle = 0.4
layer = 0.20
material = "PLA"
[build]
guard = "checkpoint"          # off | checkpoint
```

Умолчания — `DEFAULT_MANIFEST` в `doc/project.py`, там же `cache = {enabled,
budget_mb=2048, verify=false}`. `_validate_manifest` проверяет стол (три
положительных числа), сопло, слой и режим стража.

### 4.3 `params/base.yaml`

```yaml
GAP:   {value: 0.30, unit: mm, provenance: chosen, reason: "скользящая посадка"}
WALL:  {provenance: derived, expr: "5 * NOZZLE", unit: mm}
LIP_D:
  value: 0.8
  unit: mm
  provenance: assumed
  range: [0.3, 1.5]
  reason: "срисовано с фотографии"
  measure_hint: "штангенциркулем по торцу проёма"
  blocking: true            # не измерено — проект «не готов к печати»
```

Правила вида (`doc/params.py::_validate`):

| вид | обязательно | запрещено |
|---|---|---|
| `measured` | `value` (и при правке — `source`) | `expr` |
| `assumed` | `value`, `range`, значение внутри диапазона | `expr` |
| `derived` | `expr` | `value` |
| `standard`, `chosen` | `value` | `expr` |

`blocking` допустим только у `assumed`. Повтор ключа в YAML — ошибка
(свой строгий загрузчик). Поля сверх известных — ошибка.

Материал: если проект не объявил сам, по `printer.material` добавляются
`MAT_DENSITY`, `MAT_TENSILE_XY/Z`, `MAT_ELONG_XY/Z` (standard) и `MAT_E`
(assumed: модуль при изгибе с диапазоном от Z до X-Y), см. §7.4.

### 4.4 `checks/checks.yaml` и `checks/custom.py`

```yaml
- id: крышка.зацеп
  use: escape                      # имя из каталога (§8.3)
  args:
    part: "@крышка"                # ссылка на деталь
    holder: "@корпус"
    dirs: ["+Z", "+X", "-X", "+Y", "-Y"]
    gap: "${params.GAP}"           # ссылка на параметр
    hold_vol: 1.0
  severity: blocking               # blocking | warn | info

- id: подставка.стенка
  use: min_wall
  args: {part: "@подставка", exclude_zones: [язычок_1, язычок_2]}
```

В аргументах понимаются `"@деталь"`, `"${params.ИМЯ}"`, `"${expr: формула}"`
— рекурсивно в списках и словарях. Проектная проверка:

```python
from datum.doc.project import check
from datum.checks.result import CheckResult

@check("губка.против_зазора", title="губка глубже зазора")
def lip_deeper_than_gap(P):          # или (P, parts) — тогда parts("имя", u=…)
    ratio = P.LIP_D / P.GAP
    return CheckResult(..., value=ratio, op=">=", threshold=2.0)
```

### 4.5 `assembly.yaml` и `placement.yaml`

```yaml
order: [корпус, крышка]
parts:
  крышка: {method: snap, insert: "-Z", snap_vol: 320, distance: 20}
  # rigid: {method: rigid, insert: ["-Z"], tolerance: 0.05}
joints:                    # подвижные звенья собранного изделия
  крышка: {kind: revolute, axis: "-Y", origin: [0, 0, 20.2], range: [0, 105]}
  # ползун: {kind: prismatic, axis: "+X", range: [0, 25], against: [корпус]}
explode: {gap: 25}
```

`insert` — направление **вставки** (куда деталь движется, становясь на
место). Из файла выводятся проверки собираемости (§8.1). Деталь вне
`order` собирается, но её собираемость не проверяется — окно об этом
предупреждает. Шарнир (`joints:`) — жёсткое движение звена: поворот в
градусах вокруг `axis` через `origin` по правилу правой руки или сдвиг в мм;
координаты — собранной сцены, 0 — как деталь построена. Из него выводится
проверка хода `<звено>.шарнир` / `<звено>.ход` против всех других деталей
порядка (или `against`), а окно проигрывает ход ползунком (§15.6).

```yaml
# placement.yaml — пишется окном и part_place
крышка: {move: [0, 0, 12.5], rotate: [0, 0, 90]}
```

Поворот — вокруг центра габарита детали **по скрипту**, порядок осей
X→Y→Z.

### 4.6 Чужие модели — `imported/<имя>/`

`import_model` пишет транзакционно (`ops._store_model`): временный каталог →
`source.<ext>` (как был), `result.stl` (после ремонта), `meta.json` (sha256
источника, шаги ремонта, диагноз до и после).

`import_to_bed` — файл на стол деталями одним шагом (окно: «Открыть файл…»):
объекты файла читаются порознь (`geom/repair.py::load_objects`; у 3MF —
`io/read3mf.py::read_3mf_objects`, по элементу `<build>`), ремонт без
отбрасывания тел, на объект — модель и `parts/<имя>.py` (`part_source` со
сдвигом от центра стола и `Expect(bodies=None)` у многотельного). Место —
`doc/bedlayout.py::arrange`: как в файле, если в плане не перекрываются и
влезают; иначе рядами с зазором 5 мм; группа — в центр или ближайшее
свободное место. У файла многих объектов исходник модели — её объект как
прочитан (`source.stl`), а отпечаток файла и номер объекта — в `meta.json`.
Всё или ничего: отказ посередине убирает созданное. Скрипт берёт модель как
`imported("имя")` — путь не принимается, корень берётся из контекста
сборки. Отпечаток всех `meta.json` входит в ключ кеша деталей.

## 5. Геометрия — `geom/`, `std/`

`geom/` — единственный импортёр ядра manifold3d. Скрипт детали пишет
`from datum.geom import *`; имена и порядок аргументов совпадают с
`lib/mf.py` прежнего рабочего процесса CAD, чтобы скрипты корпуса
переносились механически. Модули `field`, `voxel`, `repair` в `import *` не
входят — их берут явно (`from datum.geom import field as F`).

### 5.1 Тело и журнал — `geom/solid.py`

`Solid(manifold, name, journal)` — неизменяемая обёртка над
`manifold3d.Manifold`. Ядро **ленивое**: выражение на 168 операций строится за
1.9 мс, а первый запрос свойства (`volume()`, `status()`, `num_tri()`)
форсирует всю цепочку. Поэтому правило модуля — не трогать свойства Manifold
без нужды.

- `OpRecord(index, op, args, kwargs, inputs, result, parents)` — запись
  журнала; в `result` хранится **ленивый** промежуточный Manifold (для поиска
  отказа), в `parents` — записи входных тел (слабыми ссылками: иначе предел
  журнала перестал бы ограничивать память). Журнал булевой — из ВСЕХ ветвей
  (`merge_journals`, общие предки не повторяются), ограничен 4096 записями
  (обрезается спереди).
- `Solid.wrap(...)`, `derive(man, op, **kw)`, операторы `+ - ^`
  (объединение, разность, пересечение).
- `digest()` — канонический отпечаток формы (форсирует): вершины в float32
  сортируются, грани перенумеровываются и циклически сдвигаются к
  наименьшему индексу, список граней сортируется, sha256. Прямой хеш буферов
  не годится: круг через сериализацию переставлял 122 из 132 элементов
  граней. Нужен снимкам и сверке детерминизма кеша.

### 5.2 Примитивы, булевы, преобразования

**`prims.py`** — тела задаются **границами** (`box(x0,x1,y0,y1,z0,z1)`), а не
размером и центром: так проектируют посадки. `CIRC_N = 72` (хорда 0.87 мм
при Ø20), `STEP_OVERLAP = 0.02` (перекрытие ступеней против плёнок тоньше
float32). Есть `extrude` (с закруткой и масштабом верха), `prism_xy/yz/xz`,
`cyl_x/y/z`, `cone_z`, `sphere`, `revolve_z`, `rounded_slab` (скругление
стопкой смещённых профилей — настоящего fillet в manifold3d нет; радиусы
больше толщины отвергаются; для нового — `slab` ниже).

**`features.py`** — элементы для печати. `slab(профиль, z0, z1,
chamfer_*, fillet_*)` строит СВОЮ сетку: уровни кромки — смещения контура
(`_inset`, mitre, материал слева), боковые четырёхугольники между уровнями,
крышки — `manifold3d.triangulate`; фаска ровно 45° (объём сходится с
интегралом до 1e-6), скругление — хорды дуги не длиннее `CHORD_MM`, ступенек
нет. Смещение, перевернувшее ребро или схлопнувшее контур, — отказ с
причиной. `round_corners`/`chamfer_corners` — углы в плане через буферы
shapely (форма, теряющая куски или больше половины площади, — отказ). `cup`
— стакан, `hole_z` — резец с цековкой/зенковкой. `thread` — профиль ISO
(впадина P/4, вершина P/8), закрученное выдавливание; **фаза от нуля, а не от
z0** — сечение повёрнуто на 360·z0/P, иначе винт и гайка из разных z0 не
сходились (3.6 мм³ в посадке). Зазор `clearance` обязателен: умолчания нет.
`knurl` — два встречных закрученных выдавливания, пересечённые.

**`text.py`** — надписи шрифтами (fonttools): контуры глифов уплощаются
пером, заливка — ненулевым правилом через `polygonize`; `size` — высота
заглавной (`OS/2 sCapHeight`). Шрифты ищутся по ИМЕНИ: `fonts/` проекта,
потом встроенные DejaVu (`datum/assets/fonts`, лицензия рядом); системные
(`fc-list`) — только для `fonts_list` и `font_add`, который копирует шрифт в
проект: сборка не зависит от машины. Отпечаток `fonts/` входит в ключ кеша
детали, встроенные — в `engine_digest`. Нет знака — отказ, не пропуск.
Набор — HarfBuzz (`uharfbuzz`): пары кернинга шрифта, лигатуры выключены;
кернинг не сводит буквы теснее min(щели без него, 0.6 мм) — `_kern_floor`.
`kerning=False` — прежний набор по ширинам знаков.

**Размещение** (`xform.py`): `anchor(тело, "+X-Y+Z")` — точка габарита
словами, `align`, `stack(тело, база, "+Z", gap)`, `centre_on`.

**`booleans.py`** — пакетные `union`, `diff`, `intersect` через
`Manifold.batch_boolean` (быстрее цепочки), `hull`, `compose` (без булевой —
для сцены, не для детали), `split_by_plane`. Страж здесь не вызывается, и
пустоту входов здесь не спрашивают: `is_empty()` форсирует ленивую цепочку.
Пустой вход пересечения даёт пустой ответ.

**`xform.py`** — `move`, `rotate` (градусы, вокруг начала), `rot_about`,
`mirror`, `scale`, `frame`/`place` (матрица 4×4), `array_linear`,
`array_polar`. Здесь же **единственное** определение позы печати
`UPRIGHT`/`upright(s, up)`: `+Z` — как есть, `-Z` — `rx=180`, `+Y` —
`rx=90`, `-Y` — `rx=-90`, `+X` — `ry=-90`, `-X` — `ry=90`. Ею пользуются и
проверки печатности, и экспорт.

**`profile2d.py`** — shapely → `CrossSection` (внешний контур против
часовой, дыры по часовой, EvenOdd; кольца меньше 1e-6 мм² отброшены);
`rrect_poly`, `slot_poly`, `ring_poly`, `teardrop_poly` (капля со скатами
45°, носик при печати — вверх).

**`convert.py`** — мост manifold ↔ trimesh **без** слияния вершин
(`process=False`): trimesh сливает вершины и меняет топологию, а показанное
должно совпадать с измеренным.

### 5.3 Топология и страж — `topology.py`, `guard.py`

`analyze(man)` раскладывает тело на компоненты (`decompose()`) и делит их по
**знаку объёма**: `v < 0` — запаянная полость, `|v| < 0.01 мм³` — «лезвие»
(любой знак), иначе тело. Род (genus) как признак непригоден: у «двух тел» и
у «тела с полостью» он одинаковый (таблица замера в шапке модуля). Знак
объёма компоненты — недокументированное свойство API, поэтому версия
manifold3d запинована 3.5.3, и тест держит замок.

`TopologyReport` хранит объёмы тел, полостей, лезвий и **места** (`Place`:
центр и габарит). Места в кеш не идут — кеш хранит деталь без положения.

**Страж** (`guard.checkpoint`) — замена ручных `clean()/watertight()`
корпуса. Пооперационная проверка стоила ×4.1…×9.5 (20…168 операций), а
разбор уже посчитанного тела — 0.0035 мс. Поэтому:

1. проверка — **одна**, в контрольной точке (конец скрипта детали), в
   положении детали на столе;
2. `_violations` сверяет разбор с `Expect` детали по порядку: ошибка ядра →
   пусто → вырожденный объём → число тел → запаянная полость (с местом и
   подсказкой `section(plane=…, at=…)` поперёк самого тонкого её размера) →
   род → лезвия;
3. при ошибке ядра или пустоте `locate_failure` ищет виновную операцию от
   результата к родителям (`OpRecord.parents`): жёсткая ошибка доживает до
   каждого потомка, поэтому вдоль цепочки с одним родителем — бисекция, а на
   слиянии ветвей проверяется каждая; виновник — сломанная запись с целыми
   входами, номер — её место в журнале тела.

`Expect(bodies=1, genus=None, allow_sealed_voids=False, allow_empty=False,
min_volume_mm3=1e-6, sliver_mm3=0.01, max_slivers=0)` задаётся у детали
(`@part(expect=…)`). Режимы стража: `off` и `checkpoint`.

### 5.4 Измерения — `measure.py`

Всё здесь форсирует расчёт. `vol`, `area`, `bbox`, `extents`, `centre`,
`com`, `inter_vol(a, b)` (главный измеритель интерференции), `min_gap(a, b,
search)`; сечения `section_xy/xz/yz` (вложенные контуры через
`symmetric_difference` — становятся дырами); `section_moments` (точные
моменты сечения формулами Грина — для `beam_deflection`); `ray_hit`
(расстояние считается по точке: `RayHit.distance` у manifold3d — доля
отрезка); `thickness_at`; карта занятости `occupancy`/`occupancy_ascii`.

### 5.5 Поле на сетке — `field.py`

Скульптура и органика. Замена `implicit.mesh_sdf`: `Manifold.level_set`
зовёт Python на каждую точку, и подставка под мышь (9 млн узлов)
строилась ~45 с. Здесь всё векторно на numpy.

- **Сетка и поле.** `Grid(origin, h, shape)`, `Grid.around(lo, hi, h)`
  (запас 2h, не больше 2·10⁸ узлов). `Field(grid, values)` — float32, знак
  «плюс внутри» (как в `Manifold.level_set`). Поля на разных сетках
  складывать нельзя — отказ, а не интерполяция.
- **Примитивы.** `sphere`, `box` (точное расстояние и у углов), `cyl_x/y/z`,
  `plane`, `extrude(polygon, z0, z1)`, `loft([(контур, z), …])`,
  `sdf2d(grid, polygon, *, band=None)`.
- **`sdf2d`** — плоское расстояние **своим индексом**: отрезки границы
  дробятся на куски не длиннее медианы, середины — в cKDTree, точное
  расстояние до k ближайших (k = 32, затем 128); «точно» держит сертификат
  (k-я середина дальше найденного + полудлина куска), иначе перебор
  `shapely.distance`. Расхождение с перебором — 1e-14. С `band=` точно только
  в полосе, а полоса меряется от **точек границы**, не от маски: щель уже
  клетки маска не видит. Вне полосы — оценка с ошибкой от −h/2 до +1.92h при
  точном знаке.
- **Операции.** `union/intersect/diff`, `smooth_union/intersect/diff(r)`
  (квадратичные), `offset`, `smooth(sigma_mm)` (гаусс), `redistance` —
  расстояние **от границы**, а не по градиенту (`F/|∇F|` у горизонтальной
  грани завышал в разы): в плоскости — до точек перехода нуля по осям и
  диагоналям, в объёме — до треугольников самой поверхности (0.006 мм на
  шаре).
- **`limit_overhang(f, angle=45, up="+Z")`** — проход сверху вниз: каждый
  слой не меньше слоя над ним, ужатого на `h·tg(angle)`. Ось — по `print_up`.
  Пропускается только **пустой** слой (пропуск по значению терял тонкую
  полку). На «грибе» наибольший шаг 47°.
- **Узоры.** `diagrid`, `honeycomb` (цилиндрическая развёртка, целое число
  ячеек по кругу), свой узор — функция `grid → (рёбра, фаза)`;
  `surface_pattern(f, pattern, depth, fade=…, fade_overhang=(20,35),
  soften_mm=h)` — гаснет на нависании и по маскам, сглаживается **до**
  вычитания (иначе лесенка на кромках ячеек).
- **Поверхность — `mesh(f, *, min_body_mm3=1.0, simplify=0.0)`.**
  Марширующие тетраэдры Куна на numpy: 6 тетраэдров на куб, одно разбиение
  на все кубы (диагонали общих граней совпадают), ноль — **снаружи**
  (уровень без узлов даёт многообразие), параметр на ребре не ближе 10⁻³ к
  узлу (иначе слипание во float32). Поле обкладывается рамкой −1e6 —
  поверхность у края сетки закрывается. Крупинки меньше `min_body_mm3`
  отбираются **по сетке** до сборки тела (`Manifold.compose` теряет полость),
  полости остаются стражу. Затем `simplify(tol)`.

Порядок, проверенный печатью: форма → `limit_overhang` → `redistance` →
`surface_pattern` → вычитания (гнёзда, карманы) → `mesh`.

## 6. Сборка — `build/`

### 6.1 Объявление детали — `build/part.py`

```python
# examples/latch/parts/lid.py
from datum.build import P, part
from datum.geom import box

@part("крышка", color="#c9723b", print_up="+Z")
def build():
    """Пластина толщиной LID_T под самой губкой, с печатным зазором GAP по кругу."""
    return box(P.WALL + P.GAP, P.CASE_W - P.WALL - P.GAP,
               P.WALL + P.GAP, P.CASE_D - P.WALL - P.GAP,
               P.LID_Z - P.LID_T, P.LID_Z)
# ещё: expect=Expect(...), zones=lambda: {"язычок": box(...)};
# from datum.build import bed, draft — стол и признак черновика
```

- `part(...)` кладёт `PartDef` в глобальный `PARTS`; одно имя из двух
  функций — ошибка «объявлена дважды». `print_up` — одна из шести осей
  (`PRINT_UP`); свободной строки нет, потому что «на ребре» однажды прочли
  неверно.
- `build_part(pdef, registry, *, overrides, mode, frame)`:
  прокси параметров → вызов функции → тип обязан быть `Solid` → страж в
  положении `frame(solid)` → `depends_on` = прочитанные параметры плюс
  транзитивные зависимости производных. Исключения не пробрасываются —
  ложатся в `BuildResult.error`.
- **Отпечатки кода:** `source_digest` (тело функции), `engine_digest`
  (версия manifold3d + все `.py` в `geom/`, `std/`, `build/`),
  `project_code_digest` (тело + файл детали целиком + все `lib/**/*.py` — код
  проекта, его берёт снимок), `code_digest` (`project_code_digest` +
  `engine_digest`). Ключ кеша строится по `code_digest`: правка помощника или
  самого Datum обязана сбросить кеш. В `engine_digest` входят и встроенные
  шрифты (`assets/fonts`), в ключ — отпечаток `fonts/` проекта.
- **Подсказки к ошибкам** (`build/hints.py`): к сообщению Python
  дописывается «Подсказка: …» — чужое имя → наше (`ALIASES`: `cylinder` →
  `cyl_z(d, z0, z1, …)`, `translate` → `move`, `fillet` → `slab`/
  `round_corners`), опечатка → близкое имя с подписью, неверный аргумент
  функции Datum или проверки каталога → подпись, `&` у тел → `^`, имена
  деталей одной строкой через запятую или с опечаткой → как надо. Догадки
  нет — ничего не дописывается. Работает в сборке (`describe_error`),
  загрузке скриптов, исполнителе проверок и ошибках имён проекта; тест
  держит, что каждое наше имя в таблице существует.
- **Справочник API** (`tools/apiref.py`) — `references/api.md` навыка
  собирается из `__all__`, подписей и первого абзаца документации
  (`--write`); тест сверяет файл с генерацией, так что подпись в справочнике
  не отстаёт от кода.

### 6.2 Контекст — `build/context.py`

Четыре `ContextVar`: прокси параметров, корень проекта, стол, черновик.
`P.X` / `P["X"]` читают текущий прокси (и записывают зависимость),
присваивание запрещено. `bed()` — стол (X, Y, Z) из манифеста, `draft()` —
`True` при черновой сборке. Вне сборки `P` и `bed()` бросают
`NoParamsError`.

`build/place.py`: `centre_on_bed(тело, dx, dy)` — в центр стола и на стол,
`bed_centre()` — общий сдвиг для деталей узла, построенного вокруг нуля;
`bed_warnings` — строки «у края стола» / «выходит за стол» в отчёте
`part_build` (агент, проектируя с нуля, ставил детали в угол).

`lib/` проекта импортируется как `lib.*` своим искателем в
`sys.meta_path` и **всегда из исходника** (`FreshSourceLoader`, `.pyc` не
пишется): `.pyc` сверяется по секундам и размеру, и правка «1 → 3» в ту же
секунду собиралась бы по старому коду.

### 6.3 Кеш — `build/cache.py`

Контент-адресуемый кеш в `<проект>/.datum/cache/`:

- объекты — `objects/<2 hex>/<sha256>.<ext>`, атомарная запись; меши в
  своём формате `DTMS` (заголовок, вершины float32, грани uint32), GLB для
  окна, PNG/GIF/JSON доказательств и видов;
- `index.sqlite` (WAL): `objects`, `builds(key, part, source, digest, reads,
  metrics, …)`, `part_reads(source, names)`.

**Ключ сборки** = sha256(`KERNEL_VERSION | source | kwargs | ИМЯ=значение`
только по **прочитанным** параметрам), где `source` = `code_digest` +
`+bed:XxYxZ` + `+imported:<отпечаток моделей>` + `+draft`. Поиск
перебирает все известные для этого `source` наборы прочитанных имён — так
ветвление скрипта по параметру даёт разные наборы. Сборка мусора — LRU по
времени обращения до бюджета (`cache.budget_mb`, 2048 МБ), операция
`cache_gc`.

### 6.4 Чужие модели — `build/imported.py`

`imported("имя")` → `load_mesh(result.*)` → `Solid.wrap(op="imported")`.
`imported_stamp(root)` — отпечаток всех `meta.json` (входит в ключ кеша),
`used_by(root, имя)` — кто из `parts/`/`lib/` берёт модель (нужен удалению
детали), `part_source` — шаблон скрипта «В деталь» (модель в центре стола).

### 6.5 Перила — `build/sandbox.py`

**Не граница безопасности** — защита от промаха. Ставится в воркере:

- подмена `builtins.__import__` для модулей из `parts/`, `lib/`, `checks/`:
  белый список (`datum`, `lib`, `manifold3d`, `trimesh`, `shapely`, `numpy`,
  `scipy`, `PIL`, `math`, `json`, `yaml`, `pathlib`, …) и запреты с
  объяснением (`os`, `sys`, `subprocess`, `socket`, `ctypes`, `importlib`,
  `threading`, …) → `ImportDenied`;
- запись только в проект и временный каталог: подменены `open`, `io.open`,
  `os.open` и `os.remove/rename/mkdir/chmod/…` → `WriteDenied`. Чтение не
  ограничено.

### 6.6 Воркер — `build/worker.py`

Изолируется **операция целиком**, а не сборка детали: потомок сам открывает
проект, пишет в кеш и возвращает готовый словарь — геометрию через границу
процессов передавать не нужно.

`WorkerLimits` (умолчания — решение владельца, это не настройка проекта):

| поле | умолчание | смысл |
|---|---|---|
| `cpu_seconds` | 900 | RLIMIT_CPU → SIGXCPU |
| `wall_seconds` | 1200 | астрономическое время |
| `memory_mb` | `None` | `None` — подобрать на старте: max(4096, VmSize родителя + запас) |
| `headroom_mb` | 1024 | запас сверх уже отображённого; `@op(memory_headroom_mb=4096)` расширяет |
| `file_size_mb` | 512 | RLIMIT_FSIZE |
| `open_files` | 256 | RLIMIT_NOFILE |
| `grace_seconds` | 2 | пауза SIGTERM → SIGKILL |
| `allow_network` | `False` | |

Потомок (`_child`): `setsid()`, `PR_SET_PDEATHSIG=SIGKILL`,
`mallopt(M_ARENA_MAX, 2)` (glibc резервирует по 64 МБ адресов на поток),
rlimits, `CORE=0`, запрет `connect`/`getaddrinfo` для INET, перила. Результат
— файл `result.bin` (`DTWR` + pickle + байты), не pipe. Этап работы пишется
в `stage.txt` (`stage("сборка детали X")`), потому что убитого ядром потомка
уже не спросить. Родитель опрашивает `waitpid` каждые 5 мс и пик VmSize
потомка; по дедлайну или отмене — SIGTERM группе, затем SIGKILL. Расшифровка
смерти: SIGXCPU — «исчерпан предел процессорного времени»; SIGSEGV/SIGABRT
при расходе ≥ 80 % памяти — «не хватило памяти»; иначе «упало
геометрическое ядро». Отказ называет этап и сколько он шёл.

## 7. Модель проекта — `doc/`

### 7.1 `Project` — `doc/project.py`

Центральный объект бэкенда (941 строка).

**`Project.open(path)`**: проверка, что это проект Datum → манифест →
реестр параметров + материал (`with_defaults`) → загрузка `parts/*.py` под
`use_project(root, bed)` (каждый файл — свой модуль, `FreshSourceLoader`;
`part_files[имя] = файл`) → `placement.yaml` (неизвестная деталь —
ошибка) → `checks.yaml` (YAML с `${…}` без кавычек получает подсказку) →
`assembly.yaml` → `custom.py` → `_validate_checks()`: все объявления
строятся сразу, неизвестный `use`, неверный `severity`, спор ориентаций и
повтор `id` — ошибка **при открытии**, а не в прогоне.

**`Project.build(names=None, overrides=None, *, use_cache=None,
draft=False)`**:

1. ключ-источник (§6.3) и `values = params.resolve(overrides)`;
2. **попадание**: меш из кеша → страж повторяется **всегда** → сохранённые
   число тел и полостей обязаны совпасть → в отчёт идут сохранённые
   метрики (шум float32 не попадает в снимки); при `cache.verify = true`
   деталь пересобирается и расхождение `digest` — ошибка «недетерминирован»;
3. **промах**: `build_part(..., frame=self._frame(n))` под `stage(...)`;
   в кеш кладётся тело **без положения**, `reads` — только прочитанные
   параметры;
4. поверх результата — `placement` (поворот вокруг центра габарита по
   скрипту; центр запоминается для зон и окна), пометка `draft`.

**Путь проверок — `_solid(name, proxy, **kwargs)`**: кеш в пределах
прогона (до 256 записей). Если хода нет и параметры — проектные, тело
берётся из `build()` (`_solid_built`) — то же, что показано в окне;
`check_run` после `part_build` ничего не пересобирает. Иначе (развёртка,
ход `u`) скрипт вызывается заново, поверх — положение и обязательный страж.

**`_spec_from_decl`** превращает объявление в исполнимую проверку:
подстановки `print_up` (из детали; противоречие — ошибка), `bed` и `layer`
(из манифеста), `modulus`/`density` (ссылкой `${params.MAT_E}` /
`${params.MAT_DENSITY}`, чтобы развёртка видела зависимость), `name` у
группы `machine`, `exclude_zones` → тела зон (зовётся `@part(zones=…)` с
прокси и ставится по положению детали, вокруг центра **детали**). `id`
результатов нормализуются: один результат — `id` объявления, несколько —
`id.хвост` (`крышка.зацеп.+Z`).

Остальное: `specs()`, `run_checks(overrides)` (+ публикация доказательств
в кеш, у артефакта появляется `/obj/<digest>.<ext>`), `sweep(params)`,
`summary()`, `zones(name, proxy)`, `placement_of(name)`.

### 7.2 Параметры — `params.py`, `expr.py`, `units.py`, `params_edit.py`

- **`Param`** — неизменяемая запись: `name, provenance, value` (в каноне),
  `unit, expr, range, tolerance, source, instrument, reason, ref, note,
  measure_hint, validate_with, blocking, tags, conflicts`. `range_points()`
  — точки развёртки (низ, принятое, верх).
- **`ParamRegistry`**: `load/loads`, `with_defaults`, `unknowns`
  (угаданные), `blocking_unknowns`, `resolve(overrides)` (производные
  итеративно; цикл или опечатка — ошибка со списком недостающего),
  `proxy(overrides)`, `depends_on(name)` (транзитивно), `summary()`
  (`print_ready = not blocking_unknowns`).
- **`ParamProxy`** записывает каждое прочитанное имя — отсюда `depends_on`
  деталей и проверок без ручного объявления.
- **Формулы** (`expr.py`): `ast.parse(mode="eval")` и белый список узлов;
  функции `min max abs round sqrt hypot sin cos tan asin acos atan atan2
  radians degrees floor ceil log exp`, константы `pi e tau`; каждое
  промежуточное приводится к float (защита от `9**9**9`).
- **Единицы** (`units.py`): хранится канон (мм, °, Н, МПа, г, г/см³,
  безразмерное, шт); вводить можно в мм/см/м/мкм/дюймах, рад, кгс, Па/ГПа,
  кг, %, латиницей и кириллицей.
- **Правка** (`params_edit.py`): `set_fields(text, name, fields, remove)`
  правит YAML **как текст** — понимает потоковую `{…}` и блочную формы и
  сохраняет комментарии (в них у корпуса живёт рассуждение). Запись
  атомарная. Правила (`tools/ops.py::param_set`): производный не правится;
  с `source` параметр становится `measured`, а `blocking/range/validate_with`
  снимаются; `measured` без нового источника — отказ; `assumed` без
  источника держится диапазона; после записи файл перечитывается и
  значение сверяется. Окно правит той же операцией.

### 7.3 Сборка узла и положение — `assembly.py`, `placement.py`

не влияет), поворот больше 360° — отказ; незнакомый ключ верхнего уровня

пишутся, пустой набор удаляет файл, округление), `apply(solid, placement,

### 7.4 Материалы — `materials.py`

`CATALOG`: PLA, PETG (по данным PETG Pro), ABS, ASA, TPU — числа со

## 8. Проверки — `checks/`

### 8.1 Откуда берутся проверки

1. `checks/checks.yaml` — объявления из каталога.
2. **Выведенные из `assembly.yaml`**: каждая деталь порядка, кроме первой,
   против всех предыдущих — `snap` → `snap_insertion` (`<деталь>.защёлка`),
   иначе → `assembly_path` (`<деталь>.собираемость`), обе `blocking`. Ручная
   проверка с тем же `id` перебивает выведенную.
3. `checks/custom.py` — функции `@check(id, title, group)`.

### 8.2 Исполнитель и результат — `runner.py`, `result.py`, `evidence.py`

`_run_one` вызывает проверку с прокси параметров под `stage("проверка …")`.
Исключение — результат `error` (прогон не падает); `None` — `error` («забыт
return»); пустой список — `skip`. Зависимости собираются прокси.

`CheckResult`: `id, title, status (pass|fail|warn|skip|error), message,
group, value, unit, op (>=, <=, ==, !=, in), threshold, depends_on, inputs,
evidence, severity (blocking|warn|info), duration_ms`. **Запас** `margin` —
нормированный, со знаком (`(v−t)/|t|` для `>=`; для вилки — до ближней
границы; при нулевом пороге — нет). `CheckRun.ok = есть результаты и нет
fail/error` — **пустой прогон не «OK»** («ИТОГ: НЕЧЕГО ПРОВЕРЯТЬ», код 1).
`worst` — худший по статусу, затем по запасу; отсюда «Ближе всего к краю».
Упавшая проверка получает подсказку (`build/hints.py`): неверный аргумент в
`checks.yaml` — подпись проверки и близкое имя. `check_run` называет
параметры, которых не читает ни деталь, ни проверка
(`Project.unread_params`: чтения деталей, проверок и замыкание производных,
кроме `MAT_*`; при сломанной детали — не судит), а панель параметров
помечает их «никто не читает».

Доказательства: картинка строится при провале — сечение через центр
виновной области в плоскости с наибольшим количеством материала (для
`escape` — плоскость, содержащая направление сдвига), цвета как в окне.
`insertion_force` и `flexure_force_fem` рисуют график всегда. Отказ
рисования не роняет проверку — кладётся текстовая заметка.

**Развёртка** `sweep_assumed`: опорный прогон с записью, что читает каждая
проверка → для каждого угаданного параметра — точки диапазона, гоняются
только читающие его проверки → `flips`, если вердикт меняется → попарно (до
45 пар, по 4 углам) для проверок, читающих два неизвестных. Отчёт:
«ИЗМЕРИТЬ В ПЕРВУЮ ОЧЕРЕДЬ», «СОВМЕСТНО», «Нечувствительно»,
`blocking_harmless` (помечен блокирующим, но ни на что не влияет).

### 8.3 Каталог — 35 проверок (`library.py::LIBRARY`)

У каждой записи обязательно поле `assumes` — что проверка принимает на
веру (тест не даёт завести проверку без него).

**Удержание и движение (`motion.py`)**

| проверка | что меряет | проходит, если |
|---|---|---|
| `escape` | по каждому направлению: объём пересечения при сдвиге на свободный ход `gap − free_tol` и при упоре `gap + over` | свободный ход ≤ `free_max_vol` (иначе «КЛИНИТ») и упор ≥ `hold_vol` (иначе «НЕ ДЕРЖИТ») — «держит» не касание |
| `naive_touch` | перекрытие при малом сдвиге — **устаревшая нарочно**, воспроизводит провал v3 | (info) |
| `travel_sweep` | ход детали `build(u)`: адаптивная сетка, пока самая быстрая вершина не сдвинется меньше `resolution`; пик уточняется бисекцией | max пересечения ≤ `max_inter_vol` |
| `joint_sweep` | ход звена шарнира: жёсткое движение `joint_matrix` (Родриг / сдвиг) через `travel_sweep`; в отказе — кто мешает и доказательство `pose` (худшее положение — окну) | max пересечения ≤ `max_inter_vol` |
| `stop_contact` | перебег за упор `u_over` | упор перекрывается ≥ `min_vol` |

**Собираемость (`assembly.py`)**

| проверка | что меряет | проходит, если |
|---|---|---|
| `assembly_path` | щуп уводит деталь встречно вставке от посадки (с `from_mm`), сетка не крупнее половины протяжённости + бисекция | есть направление с худшим задеванием ≤ `max_inter_vol` |
| `snap_insertion` | продавливание защёлки по пути; в `clear_at` путь обязан быть свободен | пик ≤ `max_press_vol`; иначе «СЛИШКОМ ТУГО» или «затор» |

**Посадки (`fit.py`)**: `clearance` (`min_gap` ≥ `min_mm`), `no_intersection`
(`inter_vol` ≤ `max_vol`), `obstruction_thickness` (толщина преграды вдоль
движения в сечении), `tunnel_wall` (нехватка материала в кольце вокруг
канала ≤ 2 %).

**Печатность (`printing.py`, `dfam.py`)**

| проверка | что меряет | заметки |
|---|---|---|
| `under_part_violation` | материал корпуса под подвижной деталью | «за подвижной деталью не может быть корпуса» |
| `min_wall` | размыкание сечений щупом `wall`; порог — крупнейший **связный** потерянный кусок (мм²), не доля | `exclude_zones`; режет в позе печати `up` (из `print_up`), как карта печатности |
| `overhang` | доля площади граней круче `limit_deg` | статус **warn**; `exclude_zones`; грани у стола исключены |
| `bed_contact` | площадь первого слоя в позе печати | ≥ `min_area` |
| `support_volume` | растр: ячейки без опоры в дилатации нижнего слоя на `tg θ`, объём пустоты под ними | мосты входят в объём |
| `bridge_span` | пролёт моста — ряд повисших ячеек, опёртый с двух сторон, дальше 1 мм от опоры своего слоя | ≤ `max_span` |
| `bbox_fits` | габарит в позе печати, с поворотом на 90° | доля стола ≤ 1 |

**Топология (`topology.py`)**: `single_body`, `no_sealed_void` (место и
сечение полости), `no_slivers`.

**Аналитика (`analysis.py`)**: `beam_strain` (ε = k·t·δ/L²), `flexure_force`
(вилка силы пружины-листа), `euler_buckling` (по слабой оси, коэффициент
длины по закреплению), `cam_force` (самоторможение при β+φ ≥ 90°),
`mass_estimate`, `com_support_margin` (центр масс внутри опоры с запасом),
`tipping_margin` (момент опрокидывания).

**Контакт (`contact.py`)** — `insertion_force`: (1) профиль отжатия —
в каждом положении 7 сечений, перпендикулярных вставке, с абсолютным
отступом от краёв перекрытия, бисекцией наименьшая ужимка контура до
расхождения; (2) жёсткость пружины-бруса МКЭ-вилкой; (3) наклон захода
наименьшими квадратами по внутренним точкам участка нарастания (скос
короче шага развёртки — «скоса нет»). Усилие `W = P·(μ+tgα)/(1−μ·tgα)`;
вердикт по всей вилке (порог внутри — warn).

**МКЭ (`fem.py`)** — `flexure_force_fem`: самопроверка решателя, лестница из
трёх структурированных сеток, вилка жёсткости, сверка с балочной формулой
(«работает как пластина» при широком листе).

**Детали машин (`machine.py`)** — считаются **все** виды отказа, каждый
против своего допускаемого:

| проверка | виды отказа |
|---|---|

## 9. МКЭ — `fem/`

- **Модель** (`model.py`): мм, МПа, Н; `Material(modulus, poisson)`,
  `Bar(length, width, thickness)` с плоскостями симметрии y = 0, z = 0.
- **Элемент только P2** (`solve.py::_element`, в одном месте): линейный
  тетраэдр запирается на сдвиге (−88 % на консоли). Решение —
  `skfem.solve(condense(K, f, D))`; практический предел ~17 тыс. степеней
  свободы за 1.7 с (pyamg не окупился).
- **Задачи на брусе**: `tension`, `pure_bending` (эталоны), `tip_load`,
  `guided_deflection` (торец не поворачивается). Структурированная сетка
  `MeshTet.init_tensor`, деления по ширине и толщине чётные.
- **Произвольное тело** (`solve_faces`): защемлённая и нагруженная грань
  («ось_min/ось_max» + коробка-область), допуск отбора привязан к
  **конверту мешера** fTetWild, сила делится на площадь отобранной грани.
- **Сетка** (`tetmesh.py`): fTetWild через `pytetwild`, библиотека грузится
  по пути, минуя `pytetwild.__init__` (тот тянет pyvista и VTK на 639 МБ).
  Мешер недетерминирован (199…215 узлов на одном теле).
- **Самопроверка** (`verify.py`): `verify(material)` — растяжение (1e-9) и
  поле чистого изгиба целиком (1e-6) на эталонном брусе 40×10×2;
  `patch_test(mesh)` — точное поле на всей границе **той же**
  неструктурированной сетки (на структурированной линейный элемент ложно
  проходит); `converge(levels)` — порядок сходимости и экстраполяция.
- **Вилка**: от самой мелкой сетки до экстраполяции (односторонняя:
  согласованный МКЭ жёстче точного). Экстраполяция в ответ не идёт.
- **`fem_solve`** (операция): сетка → тест заплаты на ней → решение →
  вторая сетка вдвое грубее → вилка смещения; предупреждения «сетка не
  сошлась» (>5 %) и «заделка почти точечная» (<10 % проекции). Детектор
  сингулярности: рост пиковой деформации >20 % при сошедшемся смещении
  (<5 %) и росте больше 3× процентиля 99 — по теории угла 90° (σ ~ r^−0.456,
  ×1.37 на половинном шаге); место подтверждается вогнутым ребром рядом с
  пиком.

## 10. Ввод и вывод — `io/`

### 10.1 GLB для окна — `glb.py`, `artifacts.py`

Свой писатель, не trimesh: `Trimesh(vertices, faces)` сливает вершины, и
показанное разошлось бы с измеренным. Массивы — из той же
`convert.vertices_faces`, что считает `Solid.digest()`. **Нормалей нет**:
по glTF это значит «плоская заливка» — так и должна выглядеть деталь CAD
(файл заодно втрое легче). Координаты датумовские: Z вверх, миллиметры.
Индексы uint16 до 0xFFFF вершин, иначе uint32. Цвет sRGB → линейный
`baseColorFactor`, `doubleSided: false` (при срезе видно внутрь).

`publish_glb` кладёт GLB в кеш (`kind="geom"`), отпечаток — sha256 **байтов
файла**, адрес `/obj/<digest>.glb` раздаётся с `immutable`. 1.27 млн
треугольников — 33 мс и 22 МБ.

### 10.2 Выгрузка — `export.py`, `precision.py`

Три правила модуля: поза — та же, что проверена; записанное
перечитывается; запись атомарная.

1. **Поза**: `on_bed(solid, up, bed)` = `xform.upright(print_up)` + низ на
   Z = 0 + центр в центр стола. `bed_pose` — та же поза функцией (ею
   ставятся зоны и карта печатности).
2. **float32**: ядро считает в double, STL/3MF хранят float32 — вершины,
   слипшиеся после округления, при чтении сливаются, и деталь, касающаяся
   себя точкой или ребром, выходит «не замкнута». `precision.py` находит
   пары ближе 4 шагов float32 (cKDTree), группы склеивает, и все вершины
   группы, кроме одной, сдвигает к центроиду **своих** граней на ≤ 1 мкм (до 3
   проходов). Сдвиг и изменение объёма — в отчёте.
3. **Писатели**: STL — двоичный через trimesh без обработки; 3MF — через
   lib3mf (геометрия одним куском прямым C-вызовом поверх буферов numpy,
   метаданные `Title`, `Application`, `CreationDate`, `Description` с
   вердиктом). `WriteToFile` у lib3mf переводит процесс в локаль «C» —
   вызов обёрнут в `_keep_locale()`.
4. **Сверка**: файл перечитывается, сравниваются число треугольников,
   замкнутость и объём (относительный допуск 1e-5) — с **записанной**
   сеткой. Не сошлось — файл удаляется, `ExportError`.

Выгружается **всегда** (решение владельца), но «ВНИМАНИЕ: проект не готов к
печати» — первая строка отчёта и начало `Description` в 3MF, если есть
непромеренное `blocking`, проваленные проверки или проверок нет. В отчёте
по детали — поза, габарит, треугольники, объём, разведение, поддержки,
мосты и первый слой (функциями `dfam` в той же позе). Файлы —
`output/<имя>.3mf|.stl`.

### 10.3 Чтение 3MF — `read3mf.py`

lib3mf, а не trimesh: trimesh на каждый компонент с `p:path` (так пишут
Bambu/Orca) приписывает **все** сетки части пакета (78 072 треугольника
вместо 26 024) и на 20 МБ файле съедает 2.4 ГБ. Здесь: нестрогий режим,
только элементы `<build>`, рекурсия по компонентам с матрицами (глубина ≤
32), массивы прямыми C-вызовами, перевод единиц в мм.

**Как слайсер** (с 2026-10-23): у файлов Bambu/Orca/Elegoo разметка
`Metadata/model_settings.config` задаёт тип части (`<part subtype=…>`). Ключ —
пара (объект корня, часть) по `GetModelResourceID`: номер части уникален лишь
в объекте, у копий одной сетки он общий. `normal_part` — модель,
`negative_part` — вычитается, модификатор и блокировщики поддержек — не
геометрия; элементы `printable="0"` пропускаются; имя объекта — из разметки.
Вычитание и слияние частей — в `geom/repair.py::load_objects` (`_as_printed`,
manifold3d); объект из одной части без вычитаемых — сетка из файла как есть.
Незамкнутую часть булевой не взять — тогда «НЕ ВЫЧТЕНЫ» в замечаниях.
Сверено с консольным ElegooSlicer 1.5: `--export-stls` (свой файл — совпадение
объёма до 10⁻⁷, граней и положения), `--info` (части модели), нарезка со 100 %
заполнением (вычитаемое уменьшает пластик ровно на вырезанное), положение части
— `transform` компонента, а не `matrix` разметки.

### 10.4 Нарезка ElegooSlicer — `slicer.py`, операция `slice`

Datum отдаёт проверенный 3MF и плоские профили, консольный слайсер режет и
**сам** пишет проект, который его окно откроет как свой.

- **Запуск**: `DATUM_ELEGOO_SLICER` или `elegooslicer` в PATH (у владельца —
  обёртка над AppImage в distrobox `elegoo`). Своя группа процессов
  (`start_new_session`); по таймауту 600 с — SIGTERM, затем SIGKILL **всей
  группе** (иначе умерла бы только обёртка).
- **Профили**: `~/.config/ElegooSlicer/system` (`DATUM_ELEGOO_PROFILES`),
  манифест производителя `Elegoo.json`. Имя ищется в списке **своего рода**
  и обязано быть единственным. Цепочку `inherits` разрешает Datum:
  консольный режим её не достраивает и режет со встроенными умолчаниями
  (146 ключей против проекта из окна; после разрешения — 29 служебных).
- **Выбор** (`choose`): принтер `elegoo-cc2-0.4` → «Elegoo Centauri Carbon 2
  0.4 nozzle» со сверкой сопла; процесс — с тем же `layer_height`;
  пластик — ровно один `Elegoo <материал> @…`; тип стола
  `default_bed_type` («4» = Textured PEI) ставится явно — CLI его не
  применяет. Правки `overrides` — только к существующим ключам.
- **Сверка результата**: `result.json` (`return_code 0`, один стол, число
  треугольников = детали), затем подвал G-code (полный действующий
  конфиг): имена профилей, тип стола и **каждая** правка. Не сошлось —
  файлов нет. Из подвала — время печати, граммы, слои.
- **Файлы**: временный `.datum/slice/<имя>.datum.3mf`; результат —
  `output/<имя>_<материал>.3mf` и `.gcode`.

Правки профиля (поддержки, кайма) Datum сам не выводит — их задаёт человек
или агент, с причиной. Сети у слайсера Datum не отнимает (он может слать
телеметрию, как и его окно).

## 12. Операции, CLI, MCP — `tools/`, `mcp/`

### 12.1 Реестр — `registry.py`

Операция объявляется **один раз** — асинхронной функцией с аннотациями:

```python
@op("part_build", cli_name="build", group="сборка",
    isolate=True,
    title="Собрать детали",
    summary=("Собрать деталь или все детали проекта и вернуть метрики: …"),
    exit_code=lambda r: 1 if (r.get("error") or not r.get("ok", False)) else 0)
async def part_build(
    project: Project,
    parts: Annotated[list[str] | None, Arg(help="имена деталей; пусто — все",
                                           metavar="ДЕТАЛЬ")] = None,
    draft: Annotated[bool, Arg(help="черновик: …")] = False,
) -> dict[str, Any]: ...
```

Из сигнатуры выводятся три поверхности: инструмент MCP (схема pydantic,
описание из `Arg`), подкоманда CLI (argparse) и маршрут
`POST /api/ops/<name>`. Договорённость: операция возвращает словарь, ключ
`report` — текст человеку, `error` — отказ (не исключение).

Параметры `@op`: `title`, `summary`, `group`, `danger` (`safe | mutates |
destructive` — дописывается в описание), `cli`, `mcp` (показывать ли),
`cli_name`, `exit_code`, `isolate` (в воркер), `memory_headroom_mb`.
`validate_args` — проверка REST той же схемой, что у MCP (`extra="forbid"`,
ошибки по-русски).

### 12.4 MCP — `mcp_adapter.py`, `mcp/server.py`, `remote.py`, `isolate.py`

MCP-сервер (`mcp.server.mcpserver.MCPServer`, транспорт **только stdio**,
служебный вывод — в stderr) регистрирует все операции с `mcp=True` и
краткие правила для агента (`INSTRUCTIONS`). Каждая операция обёрнута
`routed_callable`, который **на каждый вызов** выбирает, где исполнять:

1. операция без `project` — в своём процессе (изолируемая — в воркере);
2. сервер из рукопожатия (`DATUM_HANDSHAKE` — путь к файлу 0600 с портом и
   токеном, сам токен в окружение не кладётся), если он жив и проект тот
   же (pid жив + `GET /healthz` за 1 с, путь проекта совпал);
3. иначе сервер, объявивший этот проект в `$XDG_RUNTIME_DIR/datum/servers/`;
4. иначе — локально.

Запрос к серверу: `POST /api/ops/<name>` с `X-Datum-Token`,
`X-Datum-Client: 1`, `X-Datum-Actor: agent`, без прокси, таймаут 1800 с
(дольше предела воркера — чтобы ответ пришёл с причиной). У найденного
сервера параметр `project` в схеме становится необязательным.

## 13. Сервер — `server/`

### 13.1 Запуск — `run.py`

`datum serve <проект> [--port 0] [--handshake путь] [--ui каталог]
[--parent-pid pid]`: только петля (`127.0.0.1`, `localhost`, `::1`;
`0.0.0.0` отвергается), сокет открывается **заранее** и отдаётся uvicorn
(иначе окно попадало в щель между закрытием и открытием порта), сторож
родителя (сменился `getppid()` — SIGTERM себе; однажды накопилось 27
осиротевших серверов), затем объявление → файл рукопожатия → `DATUM_READY`
в stdout.

### 13.2 Маршруты — `app.py` (FastAPI)

| маршрут | назначение | токен |
|---|---|---|
| `GET /healthz` | `{ok, project, seq}` | нет |
| `GET /`, `/index.html`, `/favicon.ico` | бандл окна (`no-store`); не собран — страница с подсказкой `npm run build` | нет |
| `GET /assets/<имя>` | файл бандла, только `[A-Za-z0-9_-]+(\.[A-Za-z0-9_-]+)+`, `immutable` | нет |
| `GET /api/ops` | список операций со схемами | да |
| `POST /api/ops/{name}` | вызов и ожидание (до `wall_seconds + 60`) → `{job, status, actor, result}` | да |
| `POST /api/jobs`, `GET /api/jobs[?brief]`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/cancel` | задания без ожидания, лента, отмена | да |
| `GET /obj/{sha256}.{glb,png,gif,json,mesh,stl,3mf,step}` | объект кеша, `immutable` | да |
| `WS /ws` | события; Host и Origin петлевые (Host — в самом обработчике), токен первым кадром за 10 с | да (кадром) |

Перед вызовом `checked`: сервер подставляет **свой** проект (чужой путь —
400: «другой проект — другой сервер»), аргументы проверяются схемой.
`not_for`: операция с `mcp=False` (это `window_report`) при
`X-Datum-Actor: agent` — 403 «только для окна» (перила: «что видит человек»
агент подделывать не должен).

### 13.3 Охрана запроса — `security.py`

Порядок `ServerSecurity.check` для каждого HTTP-запроса:

1. **Host** — имя без порта обязано быть петлевым (иначе 403: «похоже на
   перепривязку DNS»);
2. открытые пути (бандл, `healthz`) — без токена: в бандле нет секретов;
3. **`X-Datum-Token`** — `hmac.compare_digest` по байтам UTF-8
   (`surrogatepass`: кириллица в заголовке не даёт 500); токен —
   `secrets.token_urlsafe(32)`;
4. **изменяющие методы** требуют `X-Datum-Client: 1` — запрос перестаёт быть
   «простым», а на предварительную проверку CORS сервер не отвечает.

Ни одного `Access-Control-*` сервер не отдаёт: на их отсутствии держится
защита от чужой страницы. CSP навешивает оболочка (§14.3).

### 13.4 Рукопожатие и объявление — `handshake.py`

Каталог `$XDG_RUNTIME_DIR/datum` (0700). Рукопожатие — одноразовый файл
0600 `{port, token, pid, project}`: не в argv (видно в `ps`) и не в
окружении (`/proc/<pid>/environ`). Объявление —
`servers/<sha256(путь)[:16]>-<pid>.json`; снимается в `lifespan` (uvicorn
перевозбуждает SIGTERM, обработчик сигнала ненадёжен), плюс `atexit` и
`finally`; мёртвые объявления (pid не жив) удаляются при чтении.

### 13.5 События, задания, наблюдение — `events.py`, `jobs.py`, `watch.py`

- **`EventHub`**: сквозной `seq`, кольцо на 1000 событий, очередь
  подписчика 512. WS-протокол: `{token, since}` → `hello {seq, project,
  complete, resync}` → пропущенное → живой поток. Отстал больше кольца —
  `resync` (окно перечитывает всё). Две задачи наперегонки (отправка и
  ожидание разрыва) — иначе uvicorn при остановке ждал вечно.
- **События**: `job.submitted|started|done|failed|cancelled`, `doc.changed`
  (пути), из результатов операций — только `geom.updated`, `artifact`,
  `log`, `window.show` (скрипт проекта не может подделать `hello` или
  `job.done`).
  События операции рассылаются **до** `job.done` — геометрия раньше, чем
  «готово».
- **`JobManager`**: последние 100 заданий; изолируемые идут через семафор
  `max(2, min(8, число ЦП))`; неизолируемые — в процессе сервера; отмена —
  SIGTERM воркеру.
- **`watch.py`**: `watchfiles` с затишьем 300 мс; интересны `datum.toml`,
  `assembly.yaml`, `placement.yaml`, `params/*.yaml`, `parts/*.py`,
  `lib/*.py`, `checks/*`, `imported/**/meta.json`; всё точечное
  (`.datum/`, `.swp`), `__pycache__`, `output/`, `snapshots/` — мимо. Сервер
  сам не пересобирает: шлёт `doc.changed`, решает окно.

## 14. Оболочка Electron — `apps/shell`

### 14.1 Запуск — `main/main.ts`

Оболочка делает ровно три вещи: поднимает Python-сервер, открывает окно на
его происхождении и отдаёт окну токен по IPC.

1. До `whenReady` — выбор видеокарты (`gpu.ts`, `DATUM_GPU`: `auto` —
   встроенная; `discrete` — PRIME + ANGLE/Vulkan; `software`).
2. `Menu.setApplicationMenu(null)` — своё меню рисует окно, а английское
   File/Edit с Ctrl+R и Ctrl+± висело бы над ним.
3. Проект: из argv; или архив `.datum` из argv → операция `unpack`; или
   пустой «Без названия».
4. `backend.start(project)` → `lockDownSession(origin)` → `createWindow`.
   Окно: `contextIsolation`, `sandbox`, без `nodeIntegration`, `webSecurity`,
   `loadURL(origin + "/")`.
5. **Гибель рендерера** (убивает нехватка памяти): `webContents.reload()`
   через 500 мс, не больше 3 раз за 2 минуты; сервер и `claude` живут в
   оболочке и не замечают падения. Сверх предела — `fatal` с советом.
6. **Сценарии проверки** (`DATUM_SCENARIO`): модуль получает `{win, app}`;
   упавший сценарий — код 1. `fatal` под сценарием выходит без диалога и
   всегда пишет причину в stderr.
7. Смена проекта — **в том же окне** (`switchProject`, с 2026-10-23; прежде
   `app.relaunch`, и окно пропадало): новый сервер → охрана сессии на его
   происхождение (`lockDownWindow` берёт происхождение функцией) → `loadURL` →
   прежний сервер гасится; `claude` останавливается. Не поднялся новый —
   остаётся прежний проект. Охрану сессии пришлось перестраивать на новый
   порт — повторный `lockDownSession` заменяет обработчики.

### 14.2 Бэкенд — `main/backend.ts`

`spawn(.venv/bin/python, -m datum.cli serve <проект> --handshake <tmp>
--ui apps/ui/dist --parent-pid <pid>)` без прокси в окружении
(`NO_PROXY` — петля). Готовность — маркер `DATUM_READY` в stdout плюс
существующий файл рукопожатия (таймаут 30 с); файл читается и сразу
удаляется. Хвост stderr (16 000 знаков) попадает в текст отказа.
Остановка: SIGTERM, через 3 с — SIGKILL.

### 14.3 Охрана окна — `main/security.ts`, `main/navigation.ts`

- Все запросы разрешений отклоняются.
- CSP на каждый ответ: `default-src 'none'; script-src 'self';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: <origin>;
  font-src 'self'; connect-src <origin> <ws-origin>; worker-src 'self' blob:;
  form-action 'none'; base-uri 'none'; frame-ancestors 'none'`.
- `window.open` — всегда отказ; `will-navigate` пускает только «свой»
  адрес; http(s) наружу уходит в системный браузер; `<webview>` запрещён.
- `navigationVerdict` сравнивает **происхождения** (`new URL().origin`), а
  не префиксы: `…:3332` — префикс чужого `…:33321`. Модуль без импорта
  electron, его берёт тест.

### 14.4 Мост окна — `preload/index.ts`

`window.datum` (через `contextBridge`, сам `ipcRenderer` наружу не отдан):
`endpoint()` (токен и проект), `platform`, `pickFile()` (диалог чужой
модели), `openProject()`, `openArchive()`, `chooseArchivePath()`,
`layout.{load, save}` (размеры панелей — файл оболочки `~/.config/datum/layout.json`,
`main/layout.ts`), `agent.{start, status, write, resize, stop, onData, onExit}`.

### 14.5 Прочее

- `untitled.ts` — пустой проект `~/.local/share/datum/untitled/untitled-
  <дата>`; нетронутый пустой берётся снова (пусты `parts/`, `imported/`,
  `snapshots/`, `lib/`, файлы не правились позже 5 с от рождения, нет
  архива); создаётся вызовом `datum init`. Решение владельца: новый
  запуск — новая работа.
- `archive.ts` — архив из argv и распаковка через CLI (охрана от враждебного
  архива живёт в одном месте — `doc/archive.py`).
- `agent.ts`, `plugin.ts`, `backlog.ts` — встроенный агент (§16).

## 15. Окно — `apps/ui`

### 15.1 Каркас

`main.tsx` → `<Fault><App/></Fault>`. Вне оболочки (нет `window.datum`)
показывается «токена взять неоткуда». Старт: `EventStream` (WS) →
`endpoint()` → `refreshAll()`; клавиши — `installHotkeys()`.

Сетка каркаса (`chrome/layout.ts` строит `grid-template-areas` только из
открытых панелей): верхняя строка (`TopBar`: меню, имя проекта, состояние,
отметка архива, «Проверить»), рейка (`Rail`), левая панель (Сцена / Модели /
Версии), вьюпорт, правая (Свойства / Проверки / Параметры), док (Claude Code
/ Лента), строка состояния, справка по клавишам, уведомления. Каждая область
— в своей границе ошибок (`fault.tsx`): сбой отрисовки панели не гасит окно.

Бандл: Vite, `target chrome152`, `assetsInlineLimit: 0` (CSP пускает
шрифты только с `'self'`), имена файлов латиницей (сервер отдаёт
`/assets/` без токена только по ASCII-шаблону). Шрифты Inter и JetBrains
Mono — в бандле.

### 15.2 Хранилища

**`store/doc`** — только то, что прислал сервер. Три правила: ответ может
опоздать (у каждого вида загрузки свой счётчик, ответ старше последнего
запроса выбрасывается); правка может прийти во время работы (флаги
«повторить после текущей сборки / прогона»); ошибка — про свою область
(`problems.project | build | checks | params | versions | models |
archive`).

Состояние: `info`, `parts` (GLB-вид по деталям), `build` (результаты сборки
и положение), `checks`, `params`, `jobs`, `snapshots`, `diff`, `models`,
`ghosts`, флаги работы, `history` для отмены (до 50).

События WS: `hello` (при `resync` — всё заново), `doc.changed` → `refreshAll`
через 250 мс затишья, `job.*` → лента, `geom.updated` → `parts[деталь]`.
`refreshAll` = сведения + параметры → (если проект открылся) сборка →
проверки, лента, образцы.

Каждое действие — вызов операции сервера (`runOp`): `setParam` →
`param_set`, `placePart` → `part_place` (+ пересборка и проверки),
`deletePart` → `part_delete`, `undo` → `part_place` с прежним положением или
`part_restore`, `saveProject` → `project_save`, `exportParts` → `export`,
`sliceParts` → `slice`, `rebuild` → `part_build {draft}`, и т. д. Своих
расчётов окно не делает.

**`store/ui`** — раскладка и инструменты: открытые панели и вкладки, высота
дока, состояние агента (`idle | starting | running | exited | failed`),
инструмент (`none | distance | probe | move | rotate`), срез (`plane`, `at`),
разнесение (`spread` 0…1), скрытые детали, видимость образцов, сетка,
черновик, уведомление (8 с, с «Вернуть»). Правило «разнесение гасит замер и
срез» — здесь, одно на всех: меню, полоса инструментов и клавиши его не
обойдут.

### 15.3 Транспорт

- `transport/client.ts::request` — единственное место заголовков:
  `X-Datum-Token`, `X-Datum-Actor: user`, на изменяющих — `X-Datum-Client: 1`.
  Запросы относительные: окно на том же происхождении.
- `transport/ws.ts::EventStream` — токен первым кадром (не в строке запроса:
  та попадает в журналы), «связь есть» — после `hello`, переподключение
  200…3000 мс.
- `transport/artifact.ts` — `/obj/…` охраняется токеном, поэтому картинки
  доказательств берутся `fetch` с заголовком и показываются blob-URL.

### 15.6 Вьюпорт — `viewport/`

Сцена — императивный класс (`scene.ts`), объектов three в состоянии React
нет; `Viewport.tsx` только связывает. Кадры рисуются **по требованию**.

- **Сцена**: Z вверх глобально (`Object3D.DEFAULT_UP`), перспективная
  камера, `OrbitControls` с приближением к курсору, полусферический +
  ключевой (тень VSM) + контровой + заполняющий свет, `RoomEnvironment`.
  Камера тени охватывает содержимое, а не стол.
- **Загрузка GLB** (`GLTFLoader` с токеном): замена по отпечатку, прежняя
  версия видна, пока грузится новая, устаревшие ответы выбрасываются;
  плоская заливка — из-за отсутствия нормалей в GLB.
- **Стол** (`plate.ts`): шейдер с сеткой 1 и 10 мм через `fwidth` (линии
  давали муар), пятно света под деталями (без него чёрная тень на почти
  чёрном полу не видна), оси, объём печати.
- **Образцы импорта**: «стекло», без теней; замер, выделение и срез их не
  ловят. Модель, которую берёт скрипт, образцом по умолчанию не
  показывается (иначе стояла бы дважды).
- **Срез** (`section.ts`): мгновенно — `clippingPlanes` three; через 120 мс
  затишья у сервера запрашиваются **точные** контуры (`section`), и по ним
  строится крышка. Числа на крышке — сервера.
- **Толщина (T)**: точка привязывается к вершине, середине ребра или
  центру грани; число считает сервер (`measure_probe`).
- **Штангенциркуль (D)** — `features.ts` разбирает сетку как ElegooSlicer
  (`libslic3r/Measure.cpp`): грани-плоскости заливкой; черты — только с
  контура грани под курсором; окружность — весь контур на окружности **и**
  с равными отрезками (иначе полукруг и скруглённый прямоугольник Gridfinity
  выходили окружностями); дуги — ≥ 5 точек и ≥ 81°; швы с изломом < 10° — не
  рёбра; обод стенки отдаёт окружность соседней грани; центр отверстия
  ловится, пока курсор внутри окружности. `caliper.ts`: первый щелчок —
  элемент (Ø, длина, нормаль), второй — расстояние (с ΔX ΔY ΔZ) или угол.
  Сетки больше 1.5 млн треугольников не разбираются.
- **Перенос и поворот** (`mover.ts`, `placement.ts`): ручки
  `TransformControls` или перетаскивание тела по горизонтали; шаг 1 мм / 15°,
  с Shift — 0.1 мм / 1°. До ответа сервера деталь едет за ручкой; на
  отпускании новое положение (кватернион → Эйлер «ZYX» = X→Y→Z у
  `Manifold.rotate`) уходит операцией `part_place`; отказ возвращает деталь.
- **Разнесение** (`explode.ts`): по `assembly.yaml` — i-я деталь встречно
  своей вставке на `gap·i`; без него — радиально. Ноль не трогает детали.
- **Ход шарниров** (`joints.ts`): ползунок на каждое звено `joints:` —
  та же матрица, что у `joint_matrix` проверки (тест сверяет числа), от
  min(0, начала) до max(0, конца). Вид, а не правка; сдвинутое звено гасит
  замер и срез, как разнесение (правило — `moved()` в `store/ui`), разнесение
  и ход сменяют друг друга. «К задеванию» ставит звено в худшее положение из
  доказательства `pose` проваленной проверки хода.
- **Куб видов и триада** (`Orientation.tsx`, `orient.ts`) — CSS 3D и SVG.
- **Отчёт окна** (`report.ts`): после 400 мс затишья изменившееся состояние
  (выделение, скрытое, инструмент, срез, разнесение, ход шарниров, камера,
  показанный замер, выбранное штангенциркулем) уходит операцией
  `window_report`.

## 16а. Симуляция механизмов и масса по настройкам печати

Два новых слоя (2026-11-08): `datum/fab` — масса печатной детали, `datum/sim` —
динамика механизма в MuJoCo 4 (`mujoco-core`, extra `sim`).

**`datum/fab`.** `settings.py` — настройки печати детали с источником каждого
числа: профиль слайсера (тот же выбор, что у `slice`) ← `[print]` в datum.toml ←
`@part(print={...})`; значение может быть именем параметра (развёртка гоняет и
его). `slicer_overrides()` — то, что уходит в `slice`. `mass.py` — масса, центр
масс и тензор инерции по слоям в позе печати: кольцо стенок (толщина по нормали
к поверхности), сплошные верх и низ, заполнение долей, подача профиля; моменты
сечений по Грину. Сверено с G-code ElegooSlicer (17 деталей Gear Cube, ±4 %);
кеш — `.datum/mass/` по отпечатку формы и настройкам.

**`datum/sim`.** `mechanism.py` — объявление без MuJoCo: звенья (дерево, у звена
не больше одного сустава к родителю), тела (печатная деталь или покупное с
массой), суставы (`revolute`, `prismatic`, ведомые `follows`), приводы
(`drive`: предел и скорость), грузы, сценарии (позы по порядку). `compile.py` —
массы звеньев (Штейнер). `model.py` — MjSpec, единственный импортёр mujoco:
рамки тел = сцена при нуле, явная инерция, контакты выключены, углы в
радианах, плотный якобиан. `run.py` — план (синхронный, минимальный рывок),
обратная динамика (нужный момент; ведомые — через матрицу связи C),
реакция основания со свободным основанием (центр давления против опорного
многоугольника), прямой прогон регулятором вычисляемого момента с пределом
привода (с ведомыми — в независимых координатах), задевания звеньев
геометрией Datum, кадры для окна. `pictures.py` — лента поз и графики моментов
растеризатором Datum.

**Проект.** `@mechanism("имя")` в parts/*.py (регистрация как у `@part`);
`Project.print_settings`, `mechanism`, `compiled_mechanism` (кеш с переносом
чтений параметров в прокси каждой проверки), `simulate` (кеш прогона на
сценарий и значения). Проверки каталога группы `sim`: `sim_drive`,
`sim_tracking`, `sim_base`, `sim_clearance` — аргументы `mechanism`, `scenario`.
Операции: `sim_list`, `sim_run` (картинки, запись для окна, событие
`sim.result`), `part_mass`. Окно — проигрыватель (`viewport/SimPlayer.tsx`).
Агенту — `references/simulation.md` (когда симулировать и что менять по
ответу). Пример — `examples/arm`.

**Реализм привода и опор (2026-11-08).** `drive(efficiency, back_efficiency,
backlash, rotor_inertia)`, `bearing(mu, radius_mm, drag, mu_axial, …)`,
`capacity(radial, axial, moment)`, `revolute(mesh_efficiency=…)`. `run.py::
_drive_loads` — трение опор по РЕАКЦИЯМ (`mj_rnePostConstraint`, `cfrc_int`,
перенесённые к оси), против движения, в покое помогает держать; ведомые — через
КПД зацепления; привод: груз ведёт — |τ|·|η_обр|·η, самотормозящий держит сам;
ротор — `armature` MuJoCo (= J_рот·i²·η). `_utilization` — карта загрузки звеньев
(привод и опора), `_backlash` — перескоки и потерянный ход. Проверки `sim_loads`,
`sim_backlash`. Откуда числа — `references/drives.md`.

**Напряжения в худший момент.** `sim/stress.py`: момент — пик |M| реакции у оси
звена; несущее тело — касающиеся печатные детали у оси (`stress_body`), куски
сетки через зазор склеены пружинами (`fem/loads.py::tie_pairs`); опора и пятна
нагрузки — по КАСАНИЮ с соседом (`geom/proximity.py`), иначе по ближайшей к оси
поверхности (сказано в ответе); нагрузки — силы и моменты следующих звеньев и
грузов (жёсткий фланец: t = F/A + ω×r), навесные тела, своё тело объёмной силой
по полю ускорений (`mj_objectAcceleration`, «a − g»). `fem/loads.py::solve_loads`
— P2, равновесие проверяется реакцией заделки; `fem/tetmesh.py::tet_meshes` —
сетки параллельно отдельными процессами (`fem/_mesh_child.py`). Вердикт —
больший пик двух сеток вне зоны опоры и пятен против `MAT_TENSILE_Z`. Проверка
`sim_stress`, операция `sim_stress` (без события), `sim_run(stress=…)`. Окно:
кнопка «Симуляция» (`viewport/SimLauncher.tsx`) — прогон, затем напряжения;
проигрыватель — карта загрузки и поле МКЭ на звене (GLB с COLOR_0).
Решатель — PARDISO (`pypardiso`, набор `mesh`) или SuperLU; замеры — docs/gpu.md.

### 17.1 Человек правит параметр в окне

```
Params.tsx ─► store/doc.setParam ─► POST /api/ops/param_set (X-Datum-Actor: user)
  сервер: checked → validate_args → JobManager (не изолируется)
    → params_edit.set_fields (текстом) → write_atomically → перечитать, сверить
  watch.py видит params/base.yaml ─► doc.changed ─► WS
окно: refreshAll ─► project_info, params_list ─► part_build (воркер)
  воркер: Project.build → ключ кеша (прочитанные параметры изменились) → промах
    → скрипт → страж → кеш → publish_glb → events: geom.updated
  сервер рассылает geom.updated, затем job.done
окно: GLTFLoader /obj/<digest>.glb → сцена; затем check_run → из кеша, без пересборки
```

### 17.2 Агент вызывает операцию

```
claude (pty) ─stdio─► python -m datum.cli mcp ─► routed_callable
  → рукопожатие из DATUM_HANDSHAKE, сервер жив, проект тот же

сервер: то же, что выше; лента окна показывает «агент»; геометрия приходит в окно
```

Если окно закрыто: MCP находит сервер по объявлению в
`$XDG_RUNTIME_DIR/datum/servers/`, а без него исполняет операцию сам

```
mover.ts (ручки) → visualOffset (до ответа) → отпускание → placementAfter

```

## 18. Охрана — сводка

Подробно — `docs/security.md`. Модель угроз: промах своего агента, чужой
проект по ссылке (архив `.datum`), чужая страница в браузере.

| слой | что держит | граница или перила |
|---|---|---|
| отдельный процесс (`build/worker.py`) | код проекта исполняется в `fork` с пределами памяти, процессора, размера файлов и дескрипторов, без сети (INET), своей группой, умирает с родителем | граница (без изоляции ядром) |
| сервер (`server/security.py`) | только петля, проверка `Host`, токен (`compare_digest`), `X-Datum-Client: 1` на изменяющих, ни одного `Access-Control-*`, `/obj/` только по шаблону sha256, WS: петлевой `Origin` + токен первым кадром | граница |
| рукопожатие (`handshake.py`) | токен в файле 0600 в каталоге 0700, не в argv и не в окружении | граница |
| окно (`apps/shell`) | `sandbox`, `contextIsolation`, CSP, мост из восьми ключей (`layout` — размеры панелей), навигация только на своё происхождение, без разрешений | граница |
| архив (`doc/archive.py`) | пути, ссылки и размер проверяются до записи; распаковывает одна операция | граница |
| перила (`build/sandbox.py`) | белый список импортов, запись только в проект | **перила**, не граница |
| `not_for` (`server/app.py`) | `window_report` недоступен агенту | **перила** |

Не сделано (записано в `docs/security.md`): изоляция чужого проекта уровнем
ядра (bwrap/unshare — пункт 3.1, отложен решением владельца),
`@electron/fuses` (нет упаковки).

Правила, которые нельзя нарушать: не добавлять `Access-Control-Allow-*`, не
вводить настроек, единственное действие которых — ослабить охрану (так уже
убраны `--host` и список разрешённых `Origin`).

## 19. Производительность и бюджеты

`scripts/budget.py` (входит в `make check`, код 1 при превышении):

| бюджет | предел |
|---|---|
| холодная сборка проекта (`latch`, `dispenser`, `spool`, `sculpt`, синтетический `gears`) | 20 с |
| горячая повторная сборка детали | 2 с |
| полный прогон проверок проекта | 60 с |
| деталь со 168 канавками | 2 с |
| страж на ней | max(5 % сборки, 5 мс) |
| поверхность поля 108×90×56 мм при шаге 0.4 (`F.mesh`) | 3 с (через `level_set` было ~45 с) |
| конвейер скульптуры целиком | 30 с |

Синтетический `gears` (четыре шестерни на 48…120 зубьев, зуб — отдельное
тело) существует потому, что на простых портах бюджет в 20 с показывал
«0.00 с» и ничего не стерёг.

Ключевые решения ради скорости: страж в контрольной точке, а не после
каждой булевой (×4…×9.5); поле на numpy вместо `level_set`; своё плоское
расстояние вместо `shapely.distance` (96 из 127 с сборки подставки); растр
через сечения вместо `contains`; 3MF через прямые C-вызовы lib3mf; кеш
проверок через кеш сборки (`check_run` после `part_build` не пересобирает);
отрисовка окна по требованию.

Пример реального проекта (подставка под мышь, после перевода на
`datum.geom.field`, 2026-10-03): сборка ~40 с, черновик 9 с, 184 тыс.
треугольников, поддержки 0 мм³.

## 23. Словарь

| термин | значение |
|---|---|
| **деталь** | Python-функция с `@part`, возвращающая `Solid` |
| **страж** | проверка топологии в контрольной точке (`geom/guard.py`): одно тело, нет запаянных полостей и лезвий |
| **запаянная полость** | компонента с отрицательным объёмом — пустота внутри тела, которую нечем заполнить при печати |
| **лезвие** | компонента объёмом < 0.01 мм³ |
| **происхождение** | `measured` (замер с источником), `assumed` (угадано, с диапазоном), `derived` (формула), `standard`, `chosen` |
| **blocking** | угаданный параметр, без замера которого проект «не готов к печати» |
| **развёртка** | `sweep_assumed`: прогон проверок по диапазонам угаданного — что решает исход |
| **вставка** (`insert`) | направление, в котором деталь движется, становясь на место (не снятия) |
| **`print_up`** | ось детали, смотрящая вверх на столе; объявляется у детали, проверки её не выбирают |
| **зона** | именованная область детали (`@part(zones=…)`), которую проверка может исключить по имени (`exclude_zones`) |
| **запас** (`margin`) | расстояние значения до порога в долях порога, со знаком |
| **вилка** | ответ МКЭ: от посчитанного на самой мелкой сетке до экстраполяции |
| **тест заплаты** | точное поле на всей границе сетки и сверка внутри — проверка элемента на той же сетке, что и расчёт |
| **образец** | чужая модель на столе как вид: не деталь, не мерится, не режется |
| **черновик** | сборка с огрублённым шагом поля (`draft()`), своя запись кеша; проверки и выгрузка его не берут |
| **поле** | `geom/field.py`: функция расстояния на равномерной сетке numpy, знак «плюс внутри» |
| **воркер** | `fork` сервера или CLI с пределами, в котором исполняется код проекта |
| **рукопожатие** | одноразовый файл 0600 с портом и токеном сервера |
| **объявление** | файл в `$XDG_RUNTIME_DIR/datum/servers/`, по которому MCP находит сервер проекта |
| **перила** | защита от промаха (`build/sandbox.py`, `not_for`), не граница безопасности |
