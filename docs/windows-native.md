# Нативный HTTP-сервер на Windows

Сервер поддерживает четыре встроенные операции: сведения о среде (`datum_status`),
каталог проверок (`check_list`), самопроверку решателя (`fem_verify`) и запись значения
параметра (`param_set`). Список доступен в `GET /api/ops` после рукопожатия.
Для записи папка проекта, каталог `params` и файлы параметров должны разрешать
изменения владельцу, администраторам и SYSTEM. Другим учётным записям допустимо
чтение. Сервер проверяет права и тип файлов перед записью.

Из рабочего каталога с установленным Python-окружением и пакетом Datum:

```powershell
.\.venv\Scripts\python.exe -I -X utf8 -m datum.cli init .\my-project
.\.venv\Scripts\python.exe -I -X utf8 -m datum.cli serve .\my-project --parent-pid $PID
```

Сервер слушает случайный порт на петлевом интерфейсе. Строка `DATUM_READY`
содержит путь к одноразовому файлу рукопожатия. Клиент читает из него порт и
токен, затем удаляет файл. По умолчанию файл находится в `LocalAppData\datum`.
Для пути, переданного через `--handshake`, нужна закрытая папка внутри
`LocalAppData`. Закрытие родительского процесса завершает сервер.

Запрос операции со скриптом проекта получает HTTP 501 до постановки в очередь.
У изолированной сборки Datum есть ограничения памяти, процессорного времени,
размера отдельного файла и числа открытых файлов. Для произвольных скриптов
исполнитель Windows с таким набором ограничений пока не реализован.
