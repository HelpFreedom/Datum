# Чем строить и что можно в скрипте детали

Читать, когда пишете или правите скрипт детали (`parts/*.py`, `lib/`).

## Чем строить

**Что есть и с какой подписью — `references/api.md`**: каждая функция
`datum.geom` и `datum.build` одной строкой, собрано из кода (тест не даёт ему
отстать). Имён из OpenSCAD, CadQuery и build123d (`cylinder`, `translate`,
`fillet`) здесь нет — ошибка импорта сама назовёт замену, а в конце
справочника они все с заменами разом. Цилиндр и отверстие задаются ДИАМЕТРОМ
и границами «от — до», `box` — границами по осям.

Элементы для печати — готовые, не рисуйте их руками:

* **Кромки плиты** — `slab(профиль, z0, z1, chamfer_bot=0.5, fillet_top=1.5)`:
  фаска ТОЧНО 45° (проверка нависаний её не считает нависанием), скругление по
  дуге без ступенек. Фаска снизу против «слоновьей ноги» — 0.4…0.6 мм. Углы в
  плане — `round_corners(профиль, r)` / `chamfer_corners` ДО выдавливания;
  радиус угла обязан быть больше кромки, иначе отказ с причиной.
  `rounded_slab` — прежний, ступенчатый: для нового — `slab`.
* **Коробка** — `cup(профиль, z0, z1, wall, floor)`.
* **Отверстие под винт** — резец `hole_z(d, z0, z1, x, y, cbore=(D, глубина))`
  или `csk=D` (зенковка 90°), вычитается `diff`; диаметр — с запасом +0.3 мм.
* **Резьба** — `thread(d, pitch, z0, z1, clearance=P.FIT)`: винт, а с
  `internal=True` — РЕЗЕЦ гайки. Зазор обязателен и задаётся параметром
  (`assumed`, ~0.15 мм, уточняется пробной печатью): угадывать его за человека
  нельзя. Фаза отсчитывается от нуля, а не от z0, — винт и гайка из одного
  проекта сходятся при любых z0. Печатать резьбу — осью вертикально: боковые
  стороны витка 60°, и лёжа на них нужны поддержки (их `support_volume` и
  покажет даже стоя — это скат витка, он печатается).
* **Накатка** — `knurl(d, z0, z1, x, y, pitch=1.5)`.
* **Надпись** — `text_z("Текст", size, z0, z1, x, y, font="DejaVu Sans Bold")`:
  `size` — высота ЗАГЛАВНОЙ буквы, мм. Штрих DejaVu Sans — восьмая часть
  высоты, у Bold — четверть: при 4 мм это одна и две линии сопла 0.4, мельче
  обычного начертания штрих не напечатается;
  выпуклая — `union`, гравировка — `diff` на 0.6…1 мм. Кириллица есть. Знака
  нет в шрифте — отказ, а не пропуск буквы. Шрифт по имени: `fonts_list` —
  какие есть (проект, встроенные, системные), `font_add(name=…)` копирует
  системный в `fonts/` проекта — проект собирается одинаково на любой машине.
  Кернинг — по таблицам шрифта (набор HarfBuzz): «AV», «To» поджимаются, но
  не теснее 0.6 мм между буквами — щель уже на печати рискует затянуться;
  у DejaVu пары есть только у латиницы. `kerning=False` — по одним ширинам,
  `spacing=` — общая разрядка (лигатур нет: каждая буква — своим знаком).
* **Размещение** — по точкам габарита: `anchor(тело, "+Z")` (центр верха,
  `"+X-Y+Z"` — угол), `align(тело, "-Z", anchor(база, "+Z"))`,
  `stack(тело, база, "+Z", gap=0.2)` — поставить сверху по центру,
  `centre_on(тело, база)`. Вместо арифметики `move(…, dz=H - h / 2 + …)`.

Параметр, который ни деталь, ни проверка не читает, `check_run` назовёт
строкой «! Параметры, которых не читает…»: размер объявлен, а деталь от него
не зависит — используйте или уберите.

## Тонко нарочно — зона, а не порог

**Тонко нарочно (упругий язычок) — объявите зону, а не поднимайте порог.**
Поднятый `max_lost_area` перестаёт ловить настоящую тонкую стенку где угодно
ещё. Вместо этого:

```python
@part("подставка", print_up="+Z",
      zones=lambda: {"язычок": box(P.TX - 1, P.TX + P.TONGUE_T + 1, 0, 12, 0, 20)})
```

и в проверке — `exclude_zones: [язычок]` (у `min_wall` и `overhang`). Зона —
функция с параметрами (`P.…`), в координатах скрипта; стоит и поворачивается
вместе с деталью. Исключённое называется в сообщении проверки и на карте
печатности — обход виден. Берите зону с запасом в миллиметр вокруг элемента.

## Гладкое сопряжение и органика

**Гладкое сопряжение — не фаска и не лестница.** Всё, что сложнее фаски,
булевыми операциями над мешами не выразить. Такие формы строятся функцией
расстояния (знак «плюс внутри», как в `Manifold.level_set`):

```python
from datum.geom.implicit import blend_union, cyl_z_sdf, sphere_sdf, mesh_sdf

f = blend_union(cyl_z_sdf(20, 0, 40), sphere_sdf(30, z=40), 6)
тело = mesh_sdf(f, bounds=(-16, -16, -1, 16, 16, 56), edge=0.5)
```

`bounds` — коробка поиска (x0, y0, z0, x1, y1, z1), и тело обязано лежать в ней
целиком: вышедшее за границу срезается плоскостью молча. Радиус значит ровно
то, что написано — проверено числом: скругление ребра бруска убирает ровно
r²·(1−π/4)·h материала.

Шаг меша `edge` — главный рычаг «точность против времени»: на шаре Ø24
погрешность объёма 0.19 % при 1 мм, 0.05 % при 0.5 мм, 0.01 % при 0.25 мм.
`mesh_sdf(..., quality=True)` строит меш ещё и вдвое грубее и возвращает
измеренный сдвиг объёма — число вместо надежды. Сопрягать стоит ПРИМИТИВЫ:
минимум и максимум дают не расстояние, а оценку снизу, и по длинной цепочке
сопряжение выходит тем хуже, чем дальше она от истинного расстояния.

**Органика и скульптура — полем на сетке (`datum.geom.field`), а не `implicit`.**
`mesh_sdf` зовёт Python на каждую точку: на подставке под мышь поверхность так
стоила ~45 с при каждой сборке. Поле на сетке — массив numpy, операции над ним
векторные, поверхность строится за доли секунды, и всё, что агент писал для
подставки руками (`lib/sculpt.py`), уже здесь. Порядок — проверенный печатью:

```python
from shapely.geometry import Point
from datum.build import P, draft, part
from datum.geom import field as F

@part("стойка", print_up="+Z")
def build():
    g = F.Grid.around((-30, -30, 0), (30, 30, 50), 1.2 if draft() else 0.4)
    body = F.loft(g, [(Point(0, 0).buffer(28), 0), (Point(0, 0).buffer(10), 22),
                      (Point(0, 0).buffer(20), 50)])        # 1. форма
    body = F.limit_overhang(body, 45, up="+Z")               # 2. до узора!
    body = F.redistance(body)                                # 3. снова расстояние
    body = F.surface_pattern(body, F.diagrid(9.0, axis_xy=(0, 0, 14)), 0.8)  # 4.
    body = F.diff(body, F.sphere(g, 40.8, 0, 0, 58))         # 5. гнёзда — последними
    return F.mesh(body, simplify=0.01)
```

- **`limit_overhang` — по форме ДО узора**: после узора он заливает нижние
  половины ячеек «зубьями». Ось — поза печати детали, ниже дна он не строит.
  Замер: шаг опоры 0.268 мм на слой при 0.250 — 47° при заданных 45°.
- **`redistance` перед узором и перед смещением**: после сопряжений и предела
  поле — не расстояние, и узор в «долинах» пробивает пузырьки (запаянные
  полости). Точность у поверхности — 0.006 мм при шаге 0.4: малый зазор
  (`offset`) ложится где сказано.
- **Узор гаснет на нависании сам** (`fade_overhang`, по СГЛАЖЕННОМУ полю —
  сырой градиент даёт «зерно», которое человек увидит, а вы — нет) и по
  маскам `fade=` (у гнёзд, кромок): поле 0…1 на той же сетке.
- **Крупинки `mesh` выбрасывает сам** (меньше `min_body_mm3`), полости
  оставляет стражу. Острое ребро поле срезает примерно на h/2: точные рёбра и
  посадки — телами (`box`, `cyl_z`), поле — для формы.
- **Черновик**: шаг берите `1.2 if draft() else 0.4` и смотрите форму
  `part_build(draft=True)` — за доли секунды. Проверки и `export` черновика не
  видят никогда.
- **Плоский контур на каждом слое** (ложемент по скану, сечения предмета) —
  `F.sdf2d(g, контур, band=мм)`: точно в полосе, дальше — оценка не хуже двух
  клеток. Полосу берите на всё, что поле решает (стенка + четверть радиуса
  сопряжения + 3σ сглаживания); без полосы контур в 1800 вершин стоил 0.3 с
  на слой. Для `loft` — без полосы: там решают и дальние значения.
- Все поля одной детали — на одной `Grid`. Пример целиком — `examples/sculpt`.

## Что можно в скрипте детали

Скрипт детали исполняется в отдельном процессе с перилами. Они ловят не злой
умысел, а привычку из старого рабочего процесса, и отказывают сразу, называя
замену.

**Импорт.** Доступны `datum.*`, геометрия и счёт (`manifold3d`, `trimesh`,
`shapely`, `numpy`, `scipy`, `build123d`), математика, обычный Python
(`dataclasses`, `itertools`, `functools`, `re`, `json`, `typing`…) и чтение
файлов (`pathlib`, `zipfile`, `tempfile`).

Запрещены и почему:

| нельзя | вместо |
|---|---|
| `os` | путями и каталогами ведает Datum; файл для слайсера пишет операция `export` |
| `sys` | деталь не правит `sys.path` и не завершает процесс: `parts/` и `lib/` подхватываются сами, результат — через `return` |
| `subprocess` | внешние программы вызываются операциями Datum, иначе результат не закешировать и не повторить |
| `socket`, `urllib`, `requests` | сети нет. Нужны данные снаружи — положите файл в проект |
| `threading`, `multiprocessing` | сборка обязана быть воспроизводимой; параллелизмом ведает Datum |
| `ctypes`, `signal`, `resource`, `gc` | обходят пределы процесса и отмену |

Ограничение касается только скриптов проекта (`parts/`, `lib/`, `checks/`).
Библиотеки импортируют что угодно — иначе не взлетел бы и numpy.

**Запись.** Писать можно в каталог проекта и во временные файлы. Попытка
записать куда-то ещё — `WriteDenied` с указанием пути. Это бережёт и чужие
каталоги (например, исходный проект, откуда перенесён скрипт), и вашу же отладку: файл, положенный
мимо проекта, потом не найти.

Перила живут внутри процесса и границей безопасности не являются — ими
служат отдельный процесс, пределы ресурсов и запрет сети. Обходить их
бессмысленно: это ровно тот случай, когда сообщение об отказе и есть ответ.

**Время.** Процессорного времени на операцию — 15 минут (по всем потокам),
астрономического — 20. Отказ по времени называет этап: «проверка X → сборка
детали Y, шёл N с» — с него и начинайте. `check_run` и `export` берут деталь
из кеша сборки, а не собирают скриптом заново: тяжёлую деталь соберите
`part_build`, дальше проверки идут за секунды. Скриптом заново собирается
только развёртка (`sweep_assumed`) и ход (`u=…`).

**Слипание во float32 — не ваша забота.** STL и 3MF хранят координаты во
float32, и вершины, разные в ядре (листы поверхности касаются точкой или
ребром), в файле слиплись бы — «меш не замкнут». `export` разводит их сам на
микрон и пишет в отчёт, сколько и на сколько. Своего `_separate_pinches` и
привязки контуров к сетке ради этого в скрипте детали не нужно.

## Gridfinity

Ящики и плиты под сетку 42 мм — `datum.std.gridfinity`, константы сверены с
эталоном (gridfinity-rebuilt-openscad). Основание не рисуют вручную:

```python
from datum.std.gridfinity import Bin, baseplate

ящик = Bin(3, 2, 6, magnets=True)             # ячейки X, Y; высота в единицах по 7 мм
ящик.pocket(88.6, 72.6, depth=20, corner_r=4)  # или shape_pocket(контур), round_pocket(⌀)
# или ящик.compartments(3, 2) — полый с перегородками
return ящик.solid()                            # по центру, низ на Z=0: print_up="+Z"
```

Высота — вместе с основанием, без губки (6 единиц = 42 мм + губка 4). Размеры
для кармана берите из `ящик.summary()` и свойств (`inner_x`, `max_depth`), а не
пересчитывайте. Кармана шире внутренности или глубже дна генератор не
построит — `GridfinityError` называет, чего не хватает; это ответ, а не
препятствие. Пример — `examples/gridfinity`.
